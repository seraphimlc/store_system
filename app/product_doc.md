# 巡店数据结算系统 · 使用手册（完整版）

> 系统地址：https://store.visitworld.me （建议电脑用 Chrome/Edge 打开）
> 文档版本：v4.0（2026-09）
>
> 本手册面向两类使用者：
> - **管理员**（万总 / 结算负责人）：管文件、对账、工资、找平；
> - **员工**（现场巡店）：看自己的绩效、申诉被滤记录。
>
> 请按顺序阅读：**一（概念）→ 二（管理员开机流程）→ 三~八（各模块说明）→ 九（员工使用）→ 十（常见问题）**。

## 一、系统解决什么问题 & 整体概念

每月有大量 Excel 巡店记录（MarsNavi 导出）和一份（或多份）结算/对账文件。系统把「从原始 Excel → 每个员工该得多少钱」整条链路搬到线上，**每一笔数据、每一次判定、每一分钱都看得见、查得到、改有据**。

### 1.1 几条核心口径（先记住）

| 概念 | 含义 |
|---|---|
| 原始数据(raw) | 上传的 Excel 原样入库，**永不改动**（可追溯底账） |
| 判定 | 每行为每行打标：有效 / 同店跨日 / 从档 / 重复导入 / 空白 |
| 正式表 | 「有效 + 员工申诉认可」的行最终入表，是算工资的依据 |
| 总点数 | 每家有效店 1 点或 2 点之和（1点+2点×2） |
| 工资 | = 点数 × 当月单价 + 奖金（单价默认 250円/点） |
| 奖金 | 每满 68 点奖 3,000円（**整月滚动、不跨月**：月初从 0 累计，余点带向下半月；下月重新从 0 开始） |
| 结算周期 | **每月发两次**：上半月(1-15) 第 20 日发；下半月(16-月末) 次月 5 日发 |
| 对账 | 拿系统的正式表 vs 每月的对账结算文件，逐员工核对 |
| 找平 | 对账差出的点数，人工确认后**记入下月**补发/扣回 |

### 1.2 一条完整数据怎么流转

```
上传 Excel（巡店原始文件）
   ↓ 自动判定（有效/被滤）
员工登录「我的申诉」对被滤记录提出申诉
管理员「绩效确认」认可或驳回
   ↓（无未处理申诉后才能入表）
「入正式表」（有效 + 认可的行）
   ↓ 可随时「月度重算」让该月按最新口径重建
绩效与工资（发薪表：上半月 / 下半月两期）
   ↓
上传对账文件（月度结算）
对账完成 → 自动归因 + AI 分析 + 生成对账结果文件
「薪资找平」页：确认每人找平值（默认全找平，可手动调整）
   ↓
下个月的绩效/对账里自动带上「上月余量」（没找完的继续递延）
```

## 二、管理员 · 开机流程（一个月从头到尾）

> 目标：让每个月从新文件到发工资，顺畅闭环。一个月的标准动作如下（**先做什么后做什么**）：

### 第 1 步：上传巡店原始文件（月度巡回文件）
1. 进「**文件上传**」页；
2. 选月份（可不选，系统自动认日期）；
3. 上传当月的 MarsNavi 巡店分卷（多个文件**逐个上传**即可，系统自动合并判重）；
4. 上传后系统自动判定，页面显示每个文件的：有效 X 条 / 过滤 Y 条（可申诉 Z 条）。
   > 提示：同一天上传的同店记录会自动去重（保留最早一次），重复的标「跨文件同日重复」，不会重复计钱。

### 第 2 步：处理申诉
1. 进「**绩效确认**」；2. 有员工申诉的先处理（认可→转为有效；驳回→定案）；
3. **某文件还有未处理申诉时，该文件不能入正式表**——先处理完再入表。

### 第 3 步：入正式表
1. 回到「文件上传」列表，每个文件点「**入正式表**」；
2. 页面会提示该文件入了多少条（有效+认可的行）。

### 第 4 步：月度重算（建议月底做一次）
1. 进「**月度重算**」选月份点「重建」；
2. 作用：把该月按最新口径（新入的文件、申诉改判、去重规则）**整体重算一遍**正式表、统计表、月绩效、薪资找平快照；
3. `同月补传新文件 / 申诉改判 / 改了单价` 之后都要重算一次，保持数字最新。

### 第 5 步：发薪（一月两次）
- **上半月发**（1-15，第 20 日）：进「**绩效与工资**」→ 顶部选「上半月(1-15)」→ 看「应该付金额」列 → 下载导出 Excel → 照表发；
- **下半月发**（16-月末，次月 5 日）：同上选「下半月(16-月末)」。

### 第 6 步：月度对账
1. 收到对账/结算文件后，进「**月度对账**」上传（选月份 + 文件）；
2. 系统自动识别表头（每月表头可能不同，必要时借助 AI）、按员工逐日比对、自动归因、生成结果文件；
3. 页面可看：差异构成、反向名单（对账漏列的人）、AI 分析、结果 Excel 下载。

### 第 7 步：薪资找平（期末清算）
1. 对账完成后，进「**薪资找平**」；
2. 每人一行：**本月对账偏差**（系统参考值）+ **找平（执行值，默认 0）**；
3. 页面上每行输入框会**预填剩余未找平**（=偏差−已找平），点「保存」即把这笔差异记入「已找平」；
4. 找平的钱会自动递延到**下月**（上月余量）参与计算——发下月工资时会体现（正=补发、负=扣回）。

## 三、绩效与工资（发薪专用，只讲钱）

> 设计原则：**这里只表达工资**，不含对账那些事（对账在「月度对账 / 薪资找平」页）。

### 3.1 两期发薪切换
- 顶部下拉选「**上半月(1-15) · 20日发**」或「**下半月(16-月末) · 次月5日发**」；
- 切到哪期，下面的表就显示那期的数据（点数、店数、成功率都是**该期**的）。

### 3.2 表格列（照表发薪）
| 列 | 含义 |
|---|---|
| 员工 / 有效店 / 点数(1/2) / 2点成功率 | 该期实际跑的店数统计 |
| **总金额(円)** | 该期点数 × 本月单价 + **该期奖金**（奖金在哪期就标在哪期，如“含奖3,000”） |
| **找平金额(円)** | 仅上半月=上月未找平余量 × 上月单价（正=补发，负=扣回，红绿标色）；下半月为 0 |
| **应该付金额(円)** | = 总金额 + 找平金额 —— **照这一列发钱** |

### 3.3 单价（円/点）怎么设
- 标题栏「单价(円/点)」输入框 + 「设置」：**默认 250**，公司调价（如改 300）就在这按月改；
- 注意：改单价**只影响改的那个月的工资/找平金额**；已确认的找平按**当时单价**锁定，不受后续调价影响（例如上月 250 元找平 10 点=2,500 元，本月涨到 300 也不变）。

### 3.4 工资/奖金/应付怎么算
- 每期总金额 = 该期点数 × 单价 + 该期奖金；
- 奖金 3,000：**每满 68 点发一个**（整月滚动、不跨月）——上半月点数÷68 的整数部分在上半月发，余数累计到下半月继续凑；
- 应付 = 总金额 + 找平金额。

## 四、薪资找平（对账后的清算表）

> 页面：导航「薪资找平」。这里是**全量对账数据**的家：偏差怎么来的、执行了多少、剩多少、递延多少，都在这。

### 4.1 页面结构
- 顶部：月份切换 + 「生成/更新」（从正式表与对账重新算一遍）+ 「导出 Excel」；
- 汇总卡：分期已发 / 奖金合计 / 对账金额 / 上月修正 / **本月对账偏差**；
- 明细表每人一行，按列分组（点/円）。

### 4.2 列含义（关键）
| 列 | 含义 |
|---|---|
| 上半月 / 下半月（点、円） | 该期系统正式表点数与该期应得工资（含奖金） |

| 分期已发(円) | 上半月+下半月应发合计 |
| 对账（点、円） | 对账文件点数及按规则折的金额 |
| 上月修正（点、円） | = **上月偏差 − 上月已找平**（上月没找完的部分递延到本月） |
| **本月对账偏差(参考)** | = 对账 − 分期已发 + 上月修正（系统自动算，不可手改，是参考依据） |
| **找平（执行）** | 人工确认实际要做的找平（默认 0） |

### 4.3 操作：怎么找平
1. 看每人「本月对账偏差」；
2. 点每行最后的「保存」——输入框默认已预填「剩余未找平（=偏差−已找平）」；
3. 直接「保存」= 把这笔差异全部找平；想部分找平就改成要执行的点数再保存；
4. 保存后该行「找平」列变为已执行值，输入框自动归 0（说明找完了）；
5. 撤销/追加：再打开输入框填负数/正数增量即可（比如已找 -190 想改，填 +10 就变成 -180）；
6. 找平金额 = 找平点数 × **该月单价**（锁存，后续调价不影响）。

### 4.4 对上个月/下个月的影响
- 「上月修正」= 上月没找完的余量，自动带进本月偏差公式；
- 所以**把该月的找平凡做完**，就不会欠到下个月；做不完的会一直递延，直到找平为零。

## 五、月度对账（与结算核对）

### 5.1 上传对账文件
1. 进「**月度对账**」→ 选月份 → 上传文件（员工点数表 或 逐条明细均可）；
2. 系统**自动识别表头**（每月不同也能识别，必要时借助 AI；识别不了会用规则兜底）；
3. 创建任务后台处理（约十几秒~分钟），完成即可查看。

### 5.2 页面能看到什么
| 内容 | 说明 |
|---|---|
| 比对人数 / 差异条数 | 该月到底多少被比对、多少有问题 |
| 员工×日对账明细（问题行） | 只列出有差异的天（日期/员工/双方点/差/说明） |
| 差异归因（系统自动） | 一致 / 仅系统有 / 仅对账有（按原因拆分：从档/跨日/重复导入），一眼看差异构成 |
| 系统有而对账文件无 | 反向名单 = 对账文件漏列的人，需人工核对 |
| 账单日文件提示 | 若对账文件日期固定一天（如 Alipay 账单日），页面会提示“按天对比数字会偏大，以人月差异为准” |
| **AI 对账分析** | 点击生成 / 任务完成自动生成“总体结论 / 差异构成 / 风险核对 / 建议动作”，大白话给管理员看 |
| 下载对账结果 Excel | 摘要+员工×日明细+差异明细+反向名单+找平确认+差异归因+AI 解读（说明列也带 AI 大白话） |

### 5.3 同月重新上传 = 重新对账
- 旧版本自动标「上一版」保留可查，新版本为当前；历史版本结果文件都能下载。

## 六、判定规则（哪些算、哪些不算）

同一家店、同一个月，**只认最早提交的那一次**；同一条记录跨文件重复导入、Visible 空白、从档（同店另一个编号）都自动滤除，并写明原因。

| 结果 | 说明 | 能否申诉 |
|---|---|---|
| 有效 | 该店该月最早的一条，自动计入绩效 | — |
| 同店跨日被顶替 | 同店该月已有更早记录 | ✅ |
| 从档归并 | 同店不同编号，主档才有效 | ✅ |
| 同日重复导入 | 同一条记录在两个文件里都出现 | ❌ |
| Visible 空白 | 没有巡店信息 | ❌ |

**点数**：每家有效店 1 点或 2 点（按日期与 Deploy 情况自动判定）。

## 七、员工使用（我的绩效 / 我的申诉）

员工首次登录（管理员告知账号）后：
1. 登录后先**改密码**（系统强制）；
2. 「**我的绩效**」：看自己当月/历史月的有效店、点数、工资（只显示本人；可按日期筛选）；
3. 「**我的申诉**」：对被滤记录（同店跨日/从档）提交申诉并写理由；
4. 处理后能看到结果（申诉成立→计入绩效；驳回→维持滤除）并留痕；
5. 「**修改密码**」：随时可改。

员工只能看/操作自己的数据，看不到工资表、对账等管理内容。

## 八、角色与权限

| 角色 | 能做什么 | 首页/默认页面 |
|---|---|---|
| 管理员 | 文件上传、判定、处理申诉、入表/月度重算、绩效与工资（两期发薪+单价设置）、月度对账、薪资找平、店铺主档、员工管理（含重置口令、启用/停用） | 绩效与工资 |

- 员工账号由系统在**上传文件时自动创建**（新编号自动建档+开户：中文名→拼音、日本名→罗马字），默认初始密码、首登强制改密；
- 管理员可在「员工管理」重置口令/停用账号。

## 九、管理员的经营页（店铺主档 / 员工管理）

- **店铺主档**：维护店铺主/从档归并（同店多个编号合并到主档），避免同一家店被算成多家；
- **员工管理**：查看员工、重置口令、启用/停用账号（停用后无法登录）。

## 十、常见问题（FAQ）

**Q：为什么我（员工）跑了店却不在绩效里？**
A：三种可能：① 该店该月已有更早的记录（同店跨日被顶替）；② 是同店另一个编号（从档）；③ Visible 为空。前两种**可申诉**。

**Q：申诉多久生效？**
A：管理员在「绩效确认」认可后，回「文件上传」对该文件点「入正式表」（或对应月份「月度重算」），该条即计入绩效。

**Q：对账显示"仅系统有/仅对账有"是出错了吗？**
A：不一定是错。对账文件口径与系统不同（例如从档也算、或对账文件漏列部分记录）都会产生差异，系统会把原因拆开列出，方便两边对齐口径。

**Q：月度重算是干什么的？**
A：把某个月按最新口径重算一遍正式表，并同步统计表、月绩效、薪资找平快照。**同月补传新文件、申诉改判、改了单价**之后需要点一次；平时不用管。

**Q：为什么有的人上半月没有奖金？**
A：奖金是「每满 68 点发一个」。如果上半月点数÷68 不够 1 个（如只有 40 点），上半月就没有奖金；这 40 点余数会累计到下半月，凑满 68 就在下半月发。

**Q：薪资找平页显示的偏差和我要执行的找平有什么区别？**
A：偏差是系统算的**参考值**（对账−分期+上月修正）；找平是你**实际决定执行**的量（默认 0，把偏差确认掉就同步）。偏差永远自动算，找平才由你掌控。

**Q：找平金额为什么和我心算的不同？**
A：偏差/找平的金额=点数 × **该月单价**；上月修正的金额=余量 × **上月单价**。因为单价可能按月调整，金额也按各自月份锁定，属正常。

**Q：同一个文件我传了两次？**
A：系统检测到同内容（sha256）会提示“该文件已存在”，不会重复导入；对账文件重传则视为“重新对账”，旧版保留为上一版。

**Q：点下载打不开？**
A：请用 Excel 打开（.xlsx）；对账结果包含多个页签（摘要、日明细、差异、归因等），切换页签查看。
