# 巡店数据结算系统 · 使用手册（交付版 v5.1）

> 系统地址：https://store.visitworld.me （建议用 Chrome / Edge 打开）
> 文档版本：v5.1（2026-10）
>
> 本手册面向：
> - **管理员**（万总 / 结算负责人）：上传文件、查看看板、核对工资、导出发薪表、修改配置；
> - **员工**（现场巡店）：查看自己的绩效与重复巡店情况。
>
> 核心结论：**每月只需「上传文件」，其余（判定、入表、工资、找平、看板统计、员工分析）全部自动完成。**

---

## 一、系统解决什么问题

每月有大量 Excel 巡店记录（MarsNavi 导出）和一份结算/对账文件。系统把「原始 Excel → 每个员工该得多少钱」整条链路搬到线上，自动完成，**每一笔数据、每一次判定、每一分钱都看得见、查得到、改有据**。

### 1.1 一条完整数据怎么流转（全自动）

```
上传 Excel（巡店原始文件）
   ↓ 自动：AI 识别表头布局 → 全部记录入库
   ↓ 自动：判重（归一化店名，同店当月只算一次）→ 每条打标（有效/重复/迟交/空白）
   ↓ 自动：有效记录入正式表（带点数，0 点不入）
   ↓ 自动：工资计算（点数×单价+奖金）→ 两期找平
   ↓ 自动：看板统计物化 → 全部员工分析预生成
   ↓ 管理员查看：数据看板 / 绩效工资 / 导出发薪表
```

**整个过程不需要人工干预**；AI 对表头布局的识别通常 1~5 秒完成。

### 1.2 核心口径（先记住）

| 概念 | 含义 |
|---|---|
| 原始数据(raw) | 上传的 Excel 原样入库，**永不改动**（可追溯底账） |
| 判定 | 每行打标：有效 / 跨文件重复 / 迟交 / 从档 / 空白 |
| 正式表 | 「有效」的行入表，是算工资的依据 |
| 点数 | 该店当月新物料=YES 记 **2 点**；S1 为 OTHER/AUDIT_SUCCESS 记 **1 点**；其它不计 |
| 工资 | = 点数 × 每点金额 + 达标奖金（可在「系统配置」修改） |
| 奖金 | 每满「达标点数」奖「达标奖金」（整月滚动、不跨月），当前 250円/点、满 75 点奖 1250円 |
| 结算周期 | **每月发两次**：上半月(1-15) 第 20 日发；下半月(16-月末) 次月 5 日发 |
| 找平 | 对账差出的金额，发薪时自动补/扣（上半月扣补→不够转下半月→递延下月） |

## 三、每月操作流程（管理员，只需 2 步）

1. **上传文件**：文件上传页 → 选择当月 Excel → 上传。
2. **等待自动完成**（通常 10~60 秒，取决于数据量）：
   - 自动判定 + 自动入正式表 + 工资/找平 + 看板统计 + 员工分析预生成；
   - 页面上方会提示「已自动入正式表 X 条，工资/找平/看板/员工分析已自动刷新」。

之后即可：查看**数据看板**、核对**绩效工资**、**导出发薪表**。同月补充上传后续文件同样自动处理（重复记录自动滤除，不会重复计分）。

> 历史说明：早期版本需要手动「入正式表」「薪资找平-生成」，现已全部自动，无需再操作。

## 四、数据看板

打开即看到当月全部经营数据（数据为**当月全月累计**，实时物化、毫秒级展示）：

- **指标卡**：总点数、工资总额、有效店/员工、1点店/2点店、2点率、人均、店均；
  （看板的「2点率」= **2点店数 ÷ 总店数**；员工自报那边另有一个「**2点分数占比**」= 2点分数 ÷ 总分数，两个口径不同，报告里会分别写明）
- **7 张图**：总点数、工资、有效店、店铺结构（1点/2点堆叠）、人员变化（员工数+新增/流失）、最新月结构（圆环）、环比对比（上月 vs 最新月）；
- **月份切换**：顶部下拉可选择历史月份（如 2026-08），指标/排行/人员/质量随所选月份切换；
- **人员与质量**：本期新增/未出现人员（表格，超 10 人可展开）、点数排行 Top8、数据质量（重复/迟交/空白占比）；
- **总体分析**（全公司）：自动生成并落盘（数据不变即秒开；数据变化自动重算）；
- **员工维度分析**：下拉选择员工 → 局部显示其逐月趋势图、明细（含**重复巡店数**）、以及自动生成的个人分析（结论+对比+归因：是市场原因、还是重复巡店太多、投放质量等）。

## 五、绩效工资与发薪表导出

- **绩效工资页**：按月分**上半月(1-15)/下半月(16-月末)**两张发薪表；每行：员工、有效店、点数(1点/2点)、2点成功率、**重复店**、奖金、总金额、找平金额、应该付金额；
- **导出 Excel**：Sheet1 发薪表（每人一行，含合计）；**每人一个明细 Sheet**（该员工本期内所有有效巡店记录：日期/店铺名/巡店时间/S1/投放/点数，逐条可对账）；
- 8 月及以前为**封账月**：数据锁定，不再随规则变化。

## 六、薪资找平（自动）

对账/结算与系统已发金额的差异自动进入找平：**差异金额 = 对账金额 − 系统已发**（负=扣款/正=补款，含奖金）。发薪时：上半月扣/补 → 不够转下半月 → 两期都不够递延下月。**全部自动**，页面只读展示，无需人工输入。

## 七、月度对账（可选）

上传当月的对账/结算文件 → 系统按员工逐笔核对 → AI 自动归因（哪些是规则差异、哪些是多发/漏发）→ 差异自动进入找平。

## 九、填报与对比（管理员）

用来核对**员工每天自报**与**文件结果**的差异。

**① 列表页（自报明细）**

- 顶部一行汇总（随筛选/区间实时变）：`自报条数 · 1点/2点店铺数 · 总点数（分数） · 2点分数占比（分子/分母）`，右侧是区间与页码；
- 每行：日期 / 员工 / 员工编号 / 担当区域 / 1点店铺数 / 2点店铺数 / 合计 / **分数（点数）** / **2点分数占比** / 提交时间 / 操作；
  - **分数（点数）= 1点店数×1 + 2点店数×2**；
  - **2点分数占比 = 2点分数 ÷ 总分数**（例：1点 6 家 / 2点 2 家 → 分数 10、占比 40%）；
- 管理员可直接**补录/修改**某人某天的自报；但**某日期 ≤ 已导入正式数据的最后一天 = 已对账 → 不能改**（列表里标「已对账」）。删除同理。

**② 对比页**

- **逐人**：系统合计 / 自报合计、**系统分数 / 自报分数**（各自的 2点分数占比写在小字里）、Δ合计 / Δ1点 / Δ2点、**准确率**、已报天数 / 系统天数、**应填未填**、AI 评语；
- **逐日明细**：每天一行，标「两侧都有 / 系统有未报 / 自报有系统无」，系统与自报的分数与占比也在行内；
- 口径：`Δ = 系统 − 自报`（正=少报、负=多报）；`准确率 = 1 − Σ|Δ| ÷ Σ系统`（**绝对值相加、不抵消**）；漏填单列、不计入准确率；
- **必须"系统 + 自报"同一天都有数据**才算得出准确率与 AI 分析；只有一侧时页面会明确提示（缺文件 / 缺自报）。

**③ 导出 Excel（两个）**

| 导出 | 内容 |
|---|---|
| 自报明细 | 日期 / 员工编号 / 姓名 / 担当区域 / 1点 / 2点 / 合计 / **分数(点数)** / **2点分数占比%** / 提交时间 / 来源 |
| 对比结果 | 按人：系统与自报的 1点/2点/合计/**分数/2点分数占比**、Δ、准确率、天数、应填未填；另附逐日明细与汇总页 |

## 十、员工管理与账号（管理员）

**账号从哪来**：上传文件时，文件里出现**新的人员编号**即自动开户（登录名按姓名自动生成拼音、初始口令为系统默认、**首次登录须改密**）；也可以在「员工管理」页**手工新建员工**（编号必填，重复只提示、不覆盖）。

**每行的「编辑」按钮** → 弹窗里改（不再在行内改）：

| 可改 | 说明 |
|---|---|
| 姓名 | 同时更新到人员档案（看板/日期计划里显示的就是它） |
| 登录名 | 员工登录用的名字；**重复会明确拒绝**（不会自动加后缀） |
| 状态 | **在岗 / 请假**：可登录；**停用 / 离职**：不能登录，但账号与历史、核算数据**永久保留**（系统不删员工） |
| 界面语言 | 中文 / 日本語 / 自动（自动=跟随浏览器） |
| 重置口令 | 留空=不改；重置后员工首次登录须自己改密 |

- **人员编号是身份键**（对账、绩效、工资、日期计划都靠它认人），弹窗里**只读**；确需修改请联系维护方。
- 停用/离职的员工在「日期计划」里**今天及以后一律按不出勤**显示（过去的日子按事实）。

> 页面上**不再展示 MCP Token**（2026-10 按要求隐藏）；相关接口与后台配置保留，需要时由维护方处理。

## 十一、员工使用

- **我的绩效**：查看本人当月/历史的有效店数、点数、工资、**重复巡店数**（重复越多效率越低）；
- **每日填报**：每天报一次担当区域 + 1点/2点店铺数（用于与文件结果对比）。
  页面上**自动算出并实时显示**：**分数（点数）= 1点店铺数×1 + 2点店铺数×2**、**2点分数占比 = 2点分数 ÷ 总分数**；今日已报回显与历史表（逐日 + 本月合计）也都有这两项；
  **核对结果**：看自己报得准不准；
- **出勤计划**：每个半月登记一次未来半个月的出勤安排。
  **填报期（提前 7 天开放，到截止日为止）**：上半月 1–15 号 → **上月 24 号 ~ 本月 3 号**；下半月 16–月末 → **本月 9 号 ~ 18 号**。
  页面是**一条一天、从上到下的半个月列表**：右边是**开关**——**开（绿色）=可出勤、关（红色）=不出勤**，
  **默认是开（可出勤）**，**点一下那天就关掉（变成不出勤），再点一下又打开**，
  从上到下点完，拉到底部按「保存出勤计划」即可（手机上也能点，不依赖脚本加载）。
  符号：**○ 可出勤 / × 不出勤 / □ 已出勤（已自报）**。
  **计划只是预报，实际出勤以每日填报为准**；已经过去的日期和已经自报的日期不会再被改动；
  填报期一过就不能再补登记；**过了截止日还没填的人，系统按下面的规则给一个默认值**（管理端用浅色标记）：**本期新入职的按「可出勤」（浅色 ○）**、**老员工按「不出勤」（浅色 ×）**。
  **登录后第一个页面**：填报期开着且本期计划还没登记 → 直接进「出勤计划」页（并有弹窗提示、底部 tab 红点）；否则进「每日填报」页。
  管理员在「**日期计划**」页可以看到全员两周内的可出勤情况（行=员工、列=日期）。**一眼读法**：

  | 显示 | 含义 |
  |---|---|
  | **○** / **×** | 员工亲手登记的：可出勤 / 不出勤 |
  | **□** | **已出勤（已自报）**——实际出勤以自报为准，它覆盖计划值 |
  | **–** | 还没登记（填报期还没过） |
  | **浅色 ○** | 没填、但按「可出勤」算（**本期新入职**，还能补填） |
  | **浅色 ×** | 没填、按「不出勤」算（**老员工漏填**，或已停用/离职） |
  | **空白** | 那天他还没入职（整期都在入职前的人不显示这一行） |

  - **过去的日子看实际结果**：那天有自报就是 **□**，没自报就是 **×**（计划值不再显示）；
  - 新入职的人**入职前的日子留空**、可以**补登本期**（登录会弹窗提醒）；
  - **今天这一列仍显示计划值**，第二天起按事实显示（自报多在傍晚提交，避免上午误读成"今天没人来"）；
  - 页面底部按日给出**计划出勤 / 实际出勤 / 未登记人数**（未登记 = 那天还没填计划的人，用来催办），
    并可导出 Excel（版式与「排班计划」一致）；
- 首次登录需修改密码；
- 员工只能看自己的数据。

## 十二、规则说明（判定与点数，9 月起固化）

1. **判重**：同一结算月、同一家店只计一次成绩（按归一化店名：全角/半角/空格/大小写差异视为同一家店），最多 2 点；
2. **点数**：① 新物料字段=YES → **2 点**（优先级最高，与审核状态无关；同店多条 YES 取最早一条，2 点归该条记录人员）；② 无 YES 时 S1 为 OTHER/AUDIT_SUCCESS → **1 点**（取最早一条）；③ 其它（AUDIT_FAILED 且无 YES 等）→ **不计成绩，不入正式表**；
3. **跨月**：记录按巡店时间归入对应结算月；8 月底的 9/1 记录归 9 月；
4. **重复巡店**：同店当月多次只保留一条，其余记为重复（影响员工效率指标，不计成绩）。

## 十三、常见问题（FAQ）

| 问题 | 回答 |
|---|---|
| 上传后需要做什么？ | 什么都不用做，系统自动完成全部；看提示「已自动入正式表…」即可 |
| 新格式的 Excel 能识别吗？ | 能。AI 自动识别表头布局（1~5 秒）；若识别不准，在「布局纠正」页调整一次，之后同格式自动识别 |
| 分析为什么是秒开/偶尔要等？ | 分析生成后落盘永久缓存；只有数据变化（如新文件入表）时才自动重算一次 |
| 为什么有的员工没有分析？ | 当期**有效店不足 5 家**就不生成（样本太少、分析没有意义）；只要当期有数据且 ≥5 家，哪怕只有一个月也会生成（没有上月数据时只跟全公司平均比，不做环比） |
| 员工重复巡店很多说明什么？ | 同店重复巡店越多效率越低，系统在绩效/看板中高亮提示，AI 分析也会给出归因 |
| 奖金怎么算？ | 每满 75 点奖 1250 円（整月滚动、不跨月）；可在「系统配置」修改 |
| 历史月份能改吗？ | 8 月及以前已封账，不随规则变化；9 月起按当前规则 |
| 对账差异怎么处理？ | 差异自动进入找平，发薪时自动补/扣，无需人工 |
| 自报里的「分数/占比」跟看板的「2点率」是一回事吗？ | 不是。自报：「分数（点数）=1点×1+2点×2」、「2点分数占比 = 2点分数÷总分数」；看板：「2点率 = 2点店数÷总店数」 |
| 日期计划里为什么有人今天之后全是 ×？ | 那是**停用/离职**的员工（按不出勤算）；没填计划的老员工过了截止日也会显示浅色 ×（"可能要离职，正常员工都会填"），本期新入职的没填则按浅色 ○ 算 |

## 十四、注意事项

- **AI 依赖**：表头识别与智能分析依赖 AI 服务（DeepSeek API）；请保障账号有效、有余额。AI 不可用时，上传仍可走默认布局/人工纠正，分析暂不生成；
- **服务器与备份**：数据在线上服务器；重要操作（改配置、批量调整）前建议导出留档；
- **数据正确性**：上传后可在「数据看板 → 数据质量」查看重复/迟交/空白占比，异常及早发现；
- **支持**：如遇 bug、数据异常或需要新功能，联系系统维护方（代码与线上已就绪，可随时交付）。
