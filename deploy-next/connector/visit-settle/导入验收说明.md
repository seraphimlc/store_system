# 连接器导入与验收说明

当前本地包是 `data/refactor/visit-settle-local.zip`，其 SHA256 见 `data/refactor/mcp-connector-acceptance.json`。包中的 `mcp.json` 已绑定本地 API `http://127.0.0.1:3000/mcp`；目标客户端导入生产或 Docker 时，应先替换为对应环境的 HTTPS 源地址，并确保 OAuth 回调和发现地址同源。

验收顺序：

1. 导入 ZIP 或连接器目录，点击“连接”。客户端应先读取受保护资源和授权服务器发现，再动态注册公共客户端。
2. 浏览器登录巡店账号；如果出现首次改密，先完成改密。授权页显示客户端名称、回调地址和 read/read-write 范围，确认后返回客户端。
3. 调用 `visit_whoami`，确认 `role`、`person_code`、`scopes` 和 `can_write` 正确。员工、队长、管理员的工具发现数量分别应为 6、10、27。
4. 员工代表流程：`visit_my_perf` 查询本人，调用管理员工具应返回 `FORBIDDEN_TOOL`；有 write scope 时可执行本人日报或本人任务进度。
5. 管理员代表流程：先对发薪导出或月重算执行预览，核对返回的 token/preview_id，再用确认语执行。对导出文件用当前账号的 Bearer 下载，不能把 URL 当成公开文件。
6. 断开后再次连接，验证 refresh token 自动轮换；重复旧 refresh 或撤销凭据后应要求重新连接。停用、离职、删除或解绑账号后，旧凭据不能继续调用。

失败判断：工具数量不对、员工能发现管理员工具、本人查询可指定他人、预演直接写财务、下载无需凭据、旧 refresh 仍可用、返回服务器路径或 Token，均视为连接器验收失败。客户端实际连接结果请记录日期、目标源地址、工具发现数量和代表流程，不把官方 SDK 或隔离 Docker 结果写成 WorkBuddy 实机结果。
