## 数据隔离

本地现有PG中新增独立库`store_settle_refactor_p1`，仅复制原schema，不复制员工数据。合成账号及权限/批次测试在该库执行，并在测试结束按创建的ID清理。原`store_settle`基线库未写入。临时开发配置保存在忽略的`.env.next.local`，只提交`.env.next.example`。

复现需要先在独立库恢复原schema并设置`NEXT_TEST_DATABASE_URL`，测试强制库名以`_refactor_p1`结尾；不能对基线或生产直接执行。密码/权限测试及浏览器脚本都会写入合成验收账号。

```bash
pnpm test:integration
pnpm typecheck
pnpm build
pnpm dev:api        # 另一个终端用 node --env-file=.env.next.local --import tsx apps/server/src/main.ts 注入配置
pnpm dev:admin      # localhost:5173/admin/
pnpm dev:staff      # localhost:5174/
pnpm test:browser   # 三个开发服务已启动；使用隔离库和本机Chrome
```

`dev:api`当前默认不自动读取任何.env，需调用者注入配置；P2统一Docker启动方式。可以通过`NEXT_BROWSER_EXECUTABLE`指定已有Chrome可执行文件；脚本使用独立临时浏览器上下文，不操作个人浏览器会话。

- 6项Node测试通过（新栈4项、P0基线2项），无跳过。包括固定Python argon2哈希验证；真实PG原结构下登录、首登改密、错误密码/停用拒绝、CSRF、改密使旧cookie失效、员工不可访问管理数据、注销、账号停用即时失效；跨队摘要隔离、离队/停用失权、账号role为staff但团队职务为leader的合法访问。
