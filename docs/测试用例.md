### 0.3 关键判定规则（写用例时的判据）
- **判重窗口** = 全库「店名 trim × Modified 所在月」分组，组内 Modified **全时间戳最早且 Visible∈{YES,NO}** 的行 → `valid`（自动生效）；同店更晚 → 同日 `cross_file_dup`、异日 `master_late`；同店名不同编号的从档 → `from_sub`；空编号/无店名 → `no_ref`；Visible 空白 → `visible_blank`（不计有效、不判重、不占锚位）。跨月不互压。
- **可申诉**仅 `master_late` / `from_sub`；`cross_file_dup` 自动滤除且员工端不出现。
- **入表门槛**：文件存在未决申诉（pending）时不入正式表；入表幂等（先删后插）。
- **两期发薪**：上半月 1-15（20 日发）、下半月 16-月末（次月 5 日发）；`上半月奖金=(上半月点÷68)×3000`，`下半月奖金=((上半月余点+下半月点)÷68)×3000`（余点带下、不跨月）。
- **找平**：偏差 `diff`=系统参考值（自动刷，不接受人工写）；找平 `adjust`=人工执行值（增量累计）；输入框值 = `diff − adjust`（剩余未找平）；`上月修正 = 上月(diff − adjust) × 上月单价` 递延。
- **CSRF**：表单缺 `csrf_token` 字段 → 422（FastAPI 校验）；值不匹配 → 400 且正文「CSRF 校验失败」；`/login` 豁免。
- **鉴权**：未登录 → 302 `/login`；员工访问管理路径 → 中间件先拦到 `/my/perf`（白名单 `/my/password`、`/my/appeal`、`/my/perf`、`/static`、`/healthz`、`/login`、`/logout`、`/product`、`/my/confirm`）；员工 `must_change_password=True` 时除改密/登出外一律 302 `/my/password?must=1`。
- **URL 别名**：旧 `/v3/*` 为别名（如 `/v3/perf`）；`/recon` 与 `/v3/recon` 等价，用例默认测无 `/v3` 主路径。

### 0.4 优先级
P0＝资金/数据正确性或阻塞主流程；P1＝重要分支与边界；P2＝体验与友好性。
