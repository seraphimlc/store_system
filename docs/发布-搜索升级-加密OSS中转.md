# 搜索升级发布：加密 ZIP 经现有 OSS 中转

2026-11-14：用户明确要求 ZIP 使用现有 OSS 中转，避免本地直传归档的速度问题。本次采用以下保密传输替代原“私有桶＋gcloud下载”路径，不修改桶权限，也不把公开桶伪称私有桶。

- 本地对 Docker 镜像归档使用随机 256 位密钥、随机 96 位 IV 的 AES-256-GCM 加密；release ID 和原归档摘要作为 AAD。
- OSS 中仅放加密 ZIP：白名单 `images.tar.gz.enc`、公开产物 manifest、`SHA256SUMS`。不含密钥、环境文件、数据库备份或运行配置。
- 密钥独立写入本地 600 权限文件，通过现有 SSH 传送至服务器 700 release 目录；不进对象存储、CDN、命令参数、日志或 Git。
- 服务器先验证下载 ZIP 大小与 SHA256、ZIP 白名单、密文摘要，再认证解密到临时文件。只有 GCM 认证和原归档摘要都通过，才改名为正式归档并导入镜像。
- 正式源码先提交并创建 `prod-YYYYMMDD-HHmmss` annotated tag；只叠搜索 API 编译模块，员工端从生产基线按白名单覆盖。管理端、Worker、任务卷和认证模块保持原版。
- 前端公开资源仍用现有 OSS/CDN，逐文件摘要、MIME 和 CORS 验证。数据库只执行已演练的 003–006 搜索日志兼容迁移，先备份，不改业务表。
- 解密后的归档及备份仅在服务器受控目录保留；本地及服务器密钥在下载解密核对成功后删除。公开密文可在上线确认后清理，不删除上一稳定镜像或 CDN。
- 此方案不是 `Cache-Control: private` 或“随机URL保密”：保密性来自认证加密，任何人即使取得 ZIP 也只有密文。禁止上传原始 `images.tar.gz`。

验证：`node --test scripts/encrypted-release-bundle.test.mjs`，覆盖往返、密文篡改、错误tag、release身份与部分明文清理。

## 运行资源核对

生产原 API 上限512MiB，小于本地大范围索引实测占用。部署前将 API 上限调整为1024MiB，仅针对本次搜索索引的已测资源需要；Worker仍512MiB，数据库与其他服务不变。服务器需确认至少足够可用内存，候选在1024MiB限制下健康再切换。该调整不意味着27万任务公网延迟已被承诺。

## 切换和回滚

保持正式 Compose 项目和生产 runtime.env，备份原状态、Compose、Nginx及数据库。检查在途业务／队列；维护窗口只替换 API／Gateway，保持 Worker 消费者数量和任务卷不变。搜索迁移只加日志字段，可回退旧 API，不删字段或回灌数据库。任何迁移、健康、版本或资源核验失败则恢复旧 API／Gateway及原 Compose，保留备份和新日志。
