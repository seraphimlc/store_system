## 三、台账空表的有意设计

- `payroll_payments` **上线初始为空，不做反填**——实发金额是历史事实，我们不知道过去各期实际发了多少，
  编造事实比留空更危险。
- **发薪事实 = 导出发薪表**（用户明确：系统无发薪反馈，导出 Excel 后离线按表发放）：
  网页 `/perf/export?month=…&period=half1|half2` 与 MCP `visit_export_salary(month, period)`
  **导出时自动登记该期台账**（金额快照；同 月×人×期 不覆盖，第一次导出即事实）。
- 更正：`visit_payroll_mark_paid(month, half, unmark=true)` 删除台账行后重新导出。
- 历史月份的结转吸收按"未标记=未发"处理，宁可保守递延、不可误扣。

## 四、回滚方案

- 迁移均为**可降级**（downgrade 已实现：删表 + 索引）。
- 若行为变化（无对账=0）引发线上问题：回滚 = 旧版本代码发布 + `alembic downgrade d4e5f6a7b8c9`（删两新表），
  `payroll_period_rows` 数据不受影响（迁移不动它）。
