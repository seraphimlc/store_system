# 店铺主档与判重工作流设计（讨论稿 v0.1）

- 日期：2026-09-04（讨论确认）
- 原则：**原始记录永不改/不乱序**；合并只发生在"主档层"元数据上；每步判定留痕可审计、可回滚。
- 配套：spec v0.4（去重/结算）、对账设计、引擎已实现。

---

## 1. 店铺表结构（store master）

每个"店铺实体"一行，字段：

| 字段 | 说明 |
|---|---|
| id | 档案行自增 id |
| store_id_raw | 原始 Store ID（MarsNavi 的 ID；一个档案行对应一个原始 ID 实体）|
| name_local / name_en | 该实体最新/规范名（展示用，原始名另存快照）|
| city / address | 城市（Tokyo 等）、地址（可选）|
| **master_store_id** | 主档指向：**自己即主档 → 指向自己；分身/别名 → 指向主档行的 id**（用户指定）|
| is_master | master_store_id == id（冗余便于查询/显示）|
| created_from_file | 建档来源（本次导入的文件 id；后续导入的新店自动建档案行）|
| created_at / updated_at / updated_by | 留痕 |
| note | 备注（为何合并/来源）|

> 用法：全店去重、员工业绩、结算一律以 **master 店**为单位；显示店名取主档行的规范名。原始 Store ID 之间的映射（如 A→主档B）只记录关系，不回写、不改动原始记录顺序。

## 2. 新导入自动建档

- 导入文件每出现一个 (store_id_raw, 店名) 实体，若主档中无此 store_id_raw → 自动新建档案行（is_master=自己）。
- 若同一 store_id_raw 后续改名/别名 → 更新档案行的名字快照（保留历史），不新建。

## 3. 判重工作流（三档 + AI 可选）

输入：现有全部/该月档案行中的"疑似同一物理店"。

**A. 程序确定性档（不开 AI 也成立）**
1. 归一化 all-trim：全半角/大小写/首尾及连续空白（NFKC 后去除空白差异），日本常见写法差异（焼き/やき、全角スペース等）作为候选依据而非直接判同。
2. 分组维度（已确认）：**同 city + 归一化店名完全相等 → 自动判为同一店**（程序直接给合并候选，仍走一次人工批量确认再落库）。
3. 归一化店名**近似组**（编辑距离小/公共子串长/逐字符差异少数个，如 `50円焼きとり　どん竜` vs `50円やきとり どん竜`）→ 生成**候选对**进入 B/C 档。

**B. AI 建议档（可插拔，无 key 时跳过）**
- 环境变量配 OpenAI 兼容 API（provider/model/key/base_url 可配，如 DeepSeek/OpenAI）。
- 把候选对（店名 Local/English、城市、地址若有、Store ID）拼成 prompt，要求输出：`同店 | 不同店 | 存疑` + 一句话理由 + 置信（高/中/低）。
- 输出仅存为**建议**，不改库。

**C. 人工裁决档（最终生效的唯一入口）**
- 页面"疑似同店"清单（按 必同/近似/AI建议 分组）：一键"确认为同店（并入主档 X）" / "不同店" / "存疑稍后"。
- 确认后：分身行的 master_store_id 指向主档行；写审计（谁、何时、依据类型：程序/AI理由/人工）。
- 支持"撤销合并"（拆回自己）。

**判定审计表 audit_links**
(id, from_store_entity_id, to_master_id, decision(merge/split/keep), basis(program_exact/program_fuzzy/ai/human), ai_reason, prompt_snapshot?, decided_by, decided_at, run_affected?)

## 4. 对结算/业绩的影响（分期实施，先不推倒重来）
- 阶段 A（本期）：建主档与自动建档 + 程序候选（精确组）+ 台账"合并/拆分"操作与审计 —— 纯附加层，**结算仍按现规则**（可对照）。
- 阶段 B：结算/去重增加"按主档"开关：同 master 店视为同一店（保留最早），未归并记录仍走原 ID/店名兜底；重跑结算对比旧结果差异清单。
- 阶段 C：AI 建议档接通（插拔 key）；对账/参考文件差异族 B-1/B-2/B-3 与主档合并结果互相印证。

## 5. 数据示例（用户给出）
```
0101047092026060971599187  50円焼きとり　どん竜
0101047092026072902976088  50円やきとり どん竜
```
归一化近似 → 候选对 → AI/人工确认 → 例如后者 master_store_id → 前者的档案 id；以后两家店的记录在结算/业绩中只算一家（保留 Modified 最早那条）。
