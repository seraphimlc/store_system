## 1. 顶层布局
```
app/               应用（main/db/models/auth/routers/services/templates/static）

scripts/           一次性/工具脚本（导入、迁移、校验、走查）
tests/             单元测试（数据/规则/流水线）
```

## 5. 业务服务（app/services/）
| 文件 | 关键函数 / 说明 |
|---|---|
| `importer.py` | `upload_and_store`（sha256 去重）、`parse_file`（Excel→raw） |
| `v3_flow.py` | **V3 主流程**：`process_import`（判定：valid/master_late/from_sub/cross_file_dup/blank + 主从档）、`finalize_import`（入表，门槛=无 pending 申诉，幂等，同步 person_daily_stats）、`rebuild_month`（月度重算，保护 approved 申诉）、`create_appeal/resolve_appeal`（申诉；accept→改判 valid，reject→维持 auto_ok）、`sync_store_for_import`（PG DISABLE TRIGGER / MySQL FK_CHECKS=0 处理自引用 FK 中间态） |
| `v3_perf.py` | `month_perf`（人月点数/工资，工资规则 68→20000+超点250）、`daily_perf`（人×日，date 键是 date 对象）、`company_summary`、`adjust_map`（找平）、`sync_month_stats/ensure_month_stats`（person_daily_stats） |
| `v3_recon.py` | 对账：`guess_kind`（person_points/daily_records）、`ai_parse_daily_cols`（**AI 表头解析**：模型读前几行→JSON 列映射，优先于规则；未配置/失败回退 _DAILY_COL_KEYS；任务 params.parser=ai/rules）、`parse_daily_records`（按 AI 列映射或规则解析；员工按姓名匹配 Person、重名选当月有正式记录者；点数列直给或 deploy 边界 2026-07-09；账单日文件标 single_date）、`start_task/run_task/launch_task`（离线线程，写 recon_data_rows/recon_day_rows/结果）、`submit_task`（同月重传→旧任务标上一版）、`attribute_daily`（**行级归因**：一致/仅系统/仅对账按原因拆分）、`interpret_task`（AI 解读，OpenAI 兼容可配）、`build_report`（Excel：摘要/日级/差异/系统独有/找平/差异归因/AI解读页签） |
| `v3_report.py` | 文件判定明细（V3）：`import_report`（基于 raw.clean_status + 申诉状态，分页/筛选）、`import_months` |
| `store_master.py` | 店铺主档：实体归一、判重、合并 |
| `ai_batch.py` | AI 判定/合并（店铺判重；对账 AI 解读在 v3_recon） |

## 9. 数据口径速查（验收数字）
见 AGENTS.md「关键基准」表（8月/7月正式表、点数、工资、对账任务）。
- 判重：月窗口 +（店名 trim，月）最早行。
- 申诉可申诉原因：`master_late`/`from_sub`。
- 对账归因：一致 = 店+时间戳两侧都有；仅系统 = 正式表有而对账无；仅对账 = 对账有而系统判滤（按原因拆分）。
- 日绩效明细：默认该月最新一天；日期/员工可筛；选员工不选日期 → 其全月。
