## 3. 迁移干跑（**首次在 PG 上跑**：只能**在线彩排**，别用 `--sql`）

⚠️ 两个坑（2026-10-06 实测踩到，别再犯）：
1. `alembic upgrade head --sql`（离线模式）**读不到当前版本** → 会把**从零初始化**的 50 多张
   `CREATE TABLE` 全打出来（那是"整套初始化"，不是"待执行"）。要带范围才行，而且
   `f9a8b7c6d5e4` 里用了 `sa.inspect(bind)` → **离线模式直接报错**，压根跑不了。
2. 干跑必须在**新镜像**里做：生产容器跑的是老代码（没有新迁移文件）→ `exec web` 干跑会"无事可做"（假象）。

✅ 正确做法 = **在生产备份还原出的临时 PG 上在线彩排**（不碰生产库）：
```bash
# 3.1 生产机上：dump 生产库 → 起临时 PG(55432) → 还原
ssh store-prod "docker exec deploy-db-1 pg_dump -U store_settle -d store_settle | gzip > /tmp/rh.sql.gz"
ssh store-prod "docker run -d --name bd_rehearsal -e POSTGRES_PASSWORD=test -e POSTGRES_USER=store_settle \
  -e POSTGRES_DB=store_settle -p 55432:5432 postgres:16-alpine"
ssh store-prod "gunzip -c /tmp/rh.sql.gz | docker exec -i bd_rehearsal psql -U store_settle -d store_settle >/dev/null"

# 3.2 用**新镜像**在临时库上真跑（--entrypoint 绕开 entrypoint 的 uvicorn；172.17.0.1 = 宿主机）
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose run --rm --entrypoint alembic \
  -e DATABASE_URL=postgresql+psycopg2://store_settle:test@172.17.0.1:55432/store_settle web upgrade head"

# 3.3 核对：版本到 head、bd_* 表数对、**结算域计数与生产一致**（证明没碰结算数据）
# 3.4 清理：docker rm -f bd_rehearsal && rm -f /tmp/rh.sql.gz
```
> 2026-10-06 这次彩排**抓到并修掉一个只在 PG 上炸的迁移 bug**（`batch_alter_table(recreate="always")`
> 撞外键）—— 见 `docs/记录-作业域.md` 的发布记录。**以后首次在新机跑迁移，务必先彩排。**
