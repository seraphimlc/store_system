## A. 业务闭环缺口

1. **同月补传文件安全重算**：判重按「店名×结算月」给全库最早一条 valid，但
   入正式表按文件 finalize。补传含更早记录的文件会造成同店同月两条 formal、
   绩效双算。→ 已提供「月度重算」页：按结算月重判全部文件 + 保护申诉认可
   成果 + 重建当月正式表（幂等）。状态：✅
2. **已入表文件申诉认可后可重新入表**：finalize 后文件行隐藏入表按钮，申诉
   认可（改判 valid）不会自动计入正式表/工资。→ 绩效确认页：文件已入表但
   valid≠formal 时显示「重新入表」按钮（finalize 幂等重建）。状态：✅
3. **对账差异后的找平闭环**：对账差异可「确认找平」→ 生成调差记录（幂等/
   可取消），记入下月工资表「上月找平」列（管理端+员工端+导出 Excel），
   金额=按工资规则折算的对账与系统工资差（正=补发/负=扣回）。状态：✅
4. **对账反向名单**：系统当月有记录而对账文件没有的员工不报警。→ 结果页已
   单独提示「系统有、对账文件未列出」名单，导出含反向 sheet。状态：✅
5. **对账差异明细导出 Excel**（差异明细 + 反向名单 + 汇总说明）。状态：✅
