# 规格 · 日期计划（半月出勤登记）

> 2026-10 交付 · 分支 `feat/date-plan`。员工在每个半月开始时登记未来半个月的可出勤情况，
> 管理员在后台看全员两周内的可出勤情况，用于分配任务。**计划只是预报，实际出勤以员工自报为准。**

## 1. 需求（用户原话归并）

- 员工在每半个月开始时做好出勤登记：每月 **3 号、18 号前**登记未来半个月的出勤设计。
- 管理员在后台能看到**所有员工两周内**的可出勤情况，便于分配任务。
- **实际出勤以自报为准**。
- 员工端：半个月的表格，**默认每天都出勤**，哪天不出勤就点选哪天。
  **叉=不出勤 / 圈=可出勤 / 方框=已出勤（已自报）**。
- 管理端：一个**大表格，行是员工、列是日期**。

## 2. 口径（已与用户确认，2026-10-01）

| 项 | 结论 |
|---|---|
| 半月划分 | **自然半月**：上半月 `1–15`（H1）、下半月 `16–月末`（H2） |
| 登记截止 | H1 → 当月 **3 号**；H2 → 当月 **18 号**（截止日当天仍可提交） |
| **填报窗口** | **提前 7 天开放，到截止日为止**：H1 = 上月 **24 号**~本月 3 号；H2 = 本月 **9 号**~18 号（2026-10-01 用户确认） |
| 窗口外 | 不能提交（`WindowClosed`）：没开 → 页面提示"X 起开放"；已关 → 无法再补登记，按"默认全部出勤"处理 |
| 锁定的日期 | 窗口内，**已过去的日期**（`< 今天`）与**已有自报的日期**不可改 |
| 「已出勤（方框）」依据 | 复用现有**员工每日填报** `staff_daily_reports`（`/my/report`）：当天有记录 = 方框 |
| 业务日 | **JST**（与每日填报一致，`daily_report.jst_today()`） |
| 代填 | **不做**（管理员不代员工登记计划） |
| 窗口关闭后未登记 | **默认全部出勤**：**今天及以后**按"默认可出勤"显示（浅色 ○，见 §3.1） |
| 待填报提示 | **窗口开着且本期未登记** → 员工端**弹窗提示**（可「稍后再说」）+ 出勤计划 tab 红点 |
| 登录落点 | 同上条件成立 → 第一个页面 = `/my/plan`（填报页）；否则 = `/my/report`（每日自报） |
| 管理端表格 | **不要"登记"列、不要未提交人名清单**：登记过的行有实色标记，没登记的行是 `–`/浅色 ○（2026-10-01 用户要求） |

- 窗口互不重叠（3 日关 → 9 日开；18 日关 → 24 日开），所以同一时刻**最多一期可填报**；
  4–8 号、19–23 号是"没有可填报期"的间隙（此间不催办、不弹窗，页面提示下个窗口）。

## 3. 三态与优先级（渲染口径，唯一来源 `date_plan.cell_state()`）

| 状态 | 符号 | 判定 | 含义 |
|---|---|---|---|
| `done` | **□** 方框 | 该日有自报（`staff_daily_reports` 有行） | 已出勤（已自报）；**优先于计划值** |
| `off` | **×** 叉 | 有计划行且 `available=0` | 计划不出勤 |
| `on` | **○** 圈 | 有计划行且 `available=1`，或"窗口关闭后未登记按默认出勤" | 可出勤（默认） |
| `none` | **–** | 该半月**没有任何计划行**（未登记，且未触发默认出勤） | 还没登记（窗口未关） |

- 优先级：`done` > 计划值 > 默认出勤 > `none`。即"已自报"覆盖一切，登记过的计划不被默认值改写。
- 管理端 `none` 用 `–` 而不是圈：**未登记 ≠ 可出勤**，避免管理员把没登记的人当成能派活。
- **默认出勤的 ○ 是浅色**（`.c.assumed`，灰色细体）：管理端一眼分清"他登记的" vs "没登记、按默认算的"。
- 人数统计里**不计入**已过去的日期（统计的是当天及以后的可用人力）。

### 3.1 窗口关闭后未登记 → 默认全部出勤（2026-10-01 用户补充）

- 判定 `date_plan.assumed_default(d, today, deadline)` = **`d >= 今天` 且 `今天 > 截止日`**。
- **只对今天及以后生效**：已经过去的日期是既成事实（有自报就是方框、没有就是未登记），
  **不追认**"默认出勤"，否则历史格子会凭空变多。
- 登记过的人不受影响：他自己标的 × 仍然是 ×（默认值优先级最低）。
- 管理端给出 **「其中默认出勤（未登记）」按日小计** + 浅色 ○ + 图例说明，
  让管理员看清楚"这是没登记所以默认算能来"，而不是"他确认能来"。
- 整期都已经过去的半月（历史半月）**不启用**该默认（`default_all` 需要 `end >= 今天`）。

## 4. 数据模型

`staff_date_plans`（新增表，**不改任何现有业务表**）

| 列 | 类型 | 说明 |
|---|---|---|
| id | Integer PK | |
| person_code | String(32) FK persons.code | 员工编号（身份键，与每日填报一致） |
| plan_date | Date | 计划日（JST 业务日） |
| available | Boolean | `1`=可出勤（圈）/ `0`=不出勤（叉） |
| source | String(16) | `web`（员工自助）/ `admin`（预留） |
| created_at / updated_at | DateTime | |

- 唯一约束 `uq_sdp_person_date`：`(person_code, plan_date)`（一天一条，重复提交=覆盖）。
- 索引 `ix_sdp_date`：`plan_date`（管理端按日期段取全员）。
- **不存 period_key**：半月归属由 `plan_date` 现算（规则若调整，历史数据不产生歧义）。
- 「该半月是否已登记」= 该人在 `[start, end]` 内是否存在计划行（无需单独的提交表）。

## 5. 服务层 `app/services/date_plan.py`

| 函数 | 作用 |
|---|---|
| `period_key(d)` / `period_bounds(key)` | 日期 ↔ `YYYY-MM-H1/H2`；返回 `(start, end, deadline)` |
| **`period_window(key)`** | 填报窗口 `(期首 − 7 天, 截止日)` |
| **`window_state(key, today)` / `is_window_open`** | `before` / `open` / `closed` |
| **`open_period(today)` / `default_period(today)` / `next_window(today)`** | 正在可填报的那一期 / 页面默认展示的那一期 / 下一个窗口 |
| `current_period(today)` / `period_options(today, back=2, fwd=1)` | 本期 / 可选半月列表（含窗口状态） |
| `is_locked(db, person_code, d, today)` | 过去了 或 已自报 → 锁定，返回原因（`past` / `reported`） |
| `plan_days(db, person_code, key, today)` | 员工端逐日视图（三态 + 窗口状态 + 可改/锁定原因 + 星期） |
| `save_plan(db, user, key, unavailable_dates, today)` | 提交/修改：**先查窗口**，再**只写未锁定的日期** |
| `is_submitted(db, person_code, key)` | 该半月是否有登记行 |
| `needs_plan(db, person_code, today)` | **现在是否还需要填报**（窗口开着 且 未登记）；返回该期信息或 `{}` |
| `staff_home(db, user)` | **员工登录后第一个页面**（单一来源）：待填报 → `/my/plan`，否则 → `/my/report`，无编号 → `/my/perf` |
| `assumed_default(d, today, deadline)` | 该日是否走"窗口关了未登记 → 默认全部出勤"（今天及以后 + 已过截止日） |
| `admin_matrix(db, key, today)` | 管理端矩阵：逐员工逐日三态 + 逐日"是否默认出勤" + 按日可出勤小计（含「其中默认出勤」） |
| `plan_xlsx(db, key, today)` | Excel 导出（员工 × 日期，符号与页面一致） |

关键实现约定：

- `save_plan` **先查窗口、再锁定、后写入**：窗口没开/已关 → `WindowClosed`；
  窗口内已过去/已自报的日期既不新增也不改写（用户明确"历史与已自报的事实不覆盖"）；
  整期都锁定时报错 `AllLocked`。
- 表单只提交**不出勤**的日期集合（`unavailable` 多值），其余按默认 `available=1` 落库；
  这样"默认每天都出勤"是数据层事实，不靠前端 JS 兜底。

## 6. 路由与页面

| 页面 | 路由 | 说明 |
|---|---|---|
| 员工端·出勤计划 | `GET /my/plan?period=` | 半月表格；`POST /my/plan` 提交（303 + `?saved/err`） |
| 管理端·日期计划 | `GET /staff-plans?period=` | 员工×日期大表格；`GET /staff-plans/export?period=` 导出 xlsx |

- 员工端 `/my/plan` 进 `main.py` 的 `STAFF_ALLOWED` 白名单，并加**底部 tabbar 第 4 项「出勤计划」**。
- 管理端顶部导航加「日期计划」（紧随「填报与对比」）。
- 权限：员工页 `role != staff → /login`；管理页 `role != admin → /my/perf`（与既有页面一致的双层防御）。
- 表单走全站一次性令牌 `{{ form_token() }}` + `csrf_token`。
- 员工端页面自带图例（×/○/□）+ **窗口状态条**（开放中 / 还没开始 / 已结束）；
  窗口间隙额外提示「下个填报期 X 开放」。
- **管理端表格只有两列文字**（员工、日期）：**没有「登记」列、不罗列未提交人名**
  （2026-10-01 用户明确「看不动」）；未提交靠"整行没有实色标记"体现，
  顶部 `未提交计划 N / M` 计数卡保留（催办用）。

### 6.1 员工落点与待填报提示（2026-10-01 用户补充）

- **落点**（`date_plan.staff_home`，三处共用同一函数，避免规则漂移）：
  ① 登录 POST（`next` 为空或 `/` 时）；② `GET /` 根跳转；③ 中间件把员工从非白名单页拦回时。
  - **窗口开着且待填报** → `/my/plan`；否则 → `/my/report`（每日自报）；未绑定编号 → `/my/perf`。
  - **首登/口令被重置**优先：登录后直接进 `/my/password?must=1`（不必先跳一次再被中间件拦住）。
  - 带 `next=` 的深链（如 OAuth `/oauth/authorize`）**不覆盖**员工落点，尊重原跳转。
- **弹窗**：中间件每个员工请求算一次 `request.state.plan_pending`，`base.html` 据此渲染弹窗
  （`data-testid="plan-prompt"`，写明填报期到哪天，「去登记」+「稍后再说」）；
  **`/my/plan` 页自身不弹**（正在填）。窗口间隙不催办（没有可填报的期）。
  用 Alpine `x-data` 但**不加 `x-cloak`**：没有 JS 时弹窗照样可见（只是「稍后再说」关不掉），
  避免 CDN 不可达时员工看不到提示。
- tab 角标：待填报时「出勤计划」tab 显示红点（弹窗被关掉后仍留提示）。
- 中间件由此**只开一次 DB 会话**（原先 must_change_password 与白名单检查各开一次），顺带跳过了 `/static`。

## 7. 边界与坑

- **H2 长度随月份变化**（28–31 天中的 16–月末 → 13–16 天），表格列数按 `period_bounds` 现算，
  不写死 15。
- **跨月的 H1/H2** 不跨月（自然半月），表格永远落在同一个自然月，表头月份清晰。
- 员工编号需绑定（`user.person_code`），未绑定 → 拒绝（与每日填报同一条约束）。
- 每日填报的**锁定规则不同**：自报锁在"已对账"（正式数据覆盖），计划锁在"已过去/已自报"，
  两者不要互相套用。
- 管理端列多（16 列）→ 外层 `.tbl-wrap` 横向滚动，≤760px 首列 sticky（现有 H5 规范）。
- **员工落点规则一变，"员工访问管理端被拦"的去向也跟着变**：`test_permission(s)` /
  `test_accounts_export` / `test_report_admin_edit` / `test_token_pages` 里断言 `/my/perf`
  的地方已统一宽松为「员工首页之一」（`/my/plan`、`/my/report`、`/my/perf`）。
- 中间件给每个员工请求多算一次 `needs_plan`（一次索引查询）；`/static` 已跳过。
- **"提前 7 天"的算法**：`期首 − 7 天`（H1 = 上月 24 日）——**不是 25 日**，
  写成 25 会少一天（测试 `test_save_plan_rejects_outside_window` 锁边界）。
- **窗口有间隙**（4–8 号、19–23 号没有任何可填报期）：此时 `needs_plan` 为假 →
  不弹窗、登录直接进自报页，员工页/管理端提示"下个填报期 X 开放"。
- **路由测试要冻结"日期计划的今天"**（`frozen` fixture：`monkeypatch.setattr(date_plan,
  "jst_today", ...)`），否则落点/弹窗用例会随真实运行日期（尤其间隙日）飘红。

## 8. 测试

`tests_web/test_date_plan.py`（49 项）：

- 半月划分：月初/月末/2 月/闰年/大小月/H2 天数/截止日；key 往返与跨年移动。
- **填报窗口**：`period_window` 边界（首尾当天算开放）、`window_state` 三态、
  `open_period` / `default_period` / `next_window`（含 4–8 号、19–23 号的间隙）、
  窗口外提交 → `WindowClosed`（before/closed 各一次）。
- 数据层：`(person_code, plan_date)` 唯一。
- 三态优先级：自报覆盖计划值；**默认出勤优先级最低**；未登记 = `none`。
- 锁定：窗口内过去的日期不改、已自报的日期不改、未来日期可改；整期都锁 → `AllLocked`。
- 默认值：只提交"不出勤"集合时其余全为可出勤；重复提交=覆盖（不产生重复行）。
- 默认出勤：`assumed_default` 边界（今天/过去/截止日当天）；矩阵里"今天及以后 ○、过去仍 –"、
  「其中默认出勤」小计、登记过的人不被默认覆盖、整期已过去的历史半月不启用。
- 待填报与落点：`needs_plan`（窗口开着才需要）/ `staff_home`、登录落点（待填报 → `/my/plan`，
  登记后或有窗口间隙 → `/my/report`）、`GET /` 同规则、
  弹窗与角标（自报页有、计划页没有、登记后消失）、弹窗写明填报期、管理员不弹。
- 员工页窗口状态条：开放中 / 还没开始 / 已结束 + 间隙提示下个窗口；非开放期无勾选框、无保存按钮。
- 管理端矩阵：**没有"登记"列、没有未提交人名清单**、按日可出勤小计、过去日期不计入统计、
  其他半月不显示"今天 0 人"、默认看正在填报的那一期。
- 路由：员工页渲染 / 提交 / 未登录跳登录 / 员工访问管理页被拦 / 管理员访问正常；
  导出 xlsx 内容与矩阵一致（含图例与默认出勤说明行）。
