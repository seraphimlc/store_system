## 0. 模型效率提示（务必遵守）

- 定位问题：先查本索引 → 再 `read` 目标文件（有行号）→ 需要时才 grep 精确关键词；
- 改代码/跑脚本：heredoc `python3 <<EOF` 在本环境**偶发静默失败** → 一律写 `scripts/*.py` 文件再执行；
- 测试：小改动只跑相关文件（如 `pytest tests_web/test_period.py -q`），大改动才全量；
- 数据查询：本地 SQLite 用 `DATABASE_URL=sqlite:///./store_settle_live.db ./.venv/bin/python` 只读验证；
- AI 配置：本地 .env / 线上 deploy/.env（AI_MODEL=deepseek-v4-flash，非 qwen）。

> **导航（2026-10-03 改）**：**管理端菜单在左侧分组**（概览｜结算｜员工｜作业｜系统｜账号，
> `base.html` 的 `aside.sidenav`，当前页高亮）；顶部只留品牌+账号+汉堡，账号操作在侧栏底部。
> **员工/队长不变**：顶部细条 + 底部 tabbar。「管理端顶栏 X」之类的旧说法一律指**左侧菜单**。

## 4. 关键数据流（速查）

```
店铺主档自动化：上传入表(auto_finalize_pipeline) → 增量建候选对(build_pairs_for_entities)
  → exact 自动合并(auto_merge_exact, 保留 id 最大为主档, 跨城市组跳过)
  → 有合并时 recompute_affected_months(受影响月=文件月∪被并实体raw月) →
    逐月 rebuild_month(+找平行同步, 返回 synced) + sync_period_table + sync_dash_metrics（best-effort）
发薪表：FormalRecord → PersonDailyStat(人×日) → sync_month_perf(月绩效物化) →
        sync_period_table(薪资找平快照: 两期点数/奖金/金额/店数) → /perf 两期视图读 half_map+half_stats
对账：ReconDataRow(对账文件全量) vs PersonDailyStats → ReconDayRow(问题行)+ReconResult(人月) →
      归因 → build_report(结果Excel) + interpret_task(AI分析) → sync_period_table 回填 settle/diff
找平：diff(系统参考,自动刷) → adjust(人工执行,输入框=剩余=偏差−已找平,保存增量累计) →
      上月余量=上月(diff−adjust)×上月单价 递延到下月 carry_map
权限：中间件 STAFF_ALLOWED 白名单 + 路由 role!=admin 双层；申诉归属校验
```

## 9.9 日期计划（半月出勤登记，2026-10 交付 · 分支 feat/date-plan）

- **需求**：员工在每个半月开始时登记未来半个月的出勤（每月 **3 号 / 18 号前**），管理员据此分配任务；  
  **实际出勤以自报为准**。规格 `docs/specs-date-plan.md`。
- **半月口径**：自然半月 `1–15`（H1，截止 3 号）/ `16–月末`（H2，截止 18 号）；H2 天数随月份 13–16 天，**不写死 15**。
- **填报窗口（2026-10-01 补充）**：**提前 7 天开放 → 到截止日为止**（`period_window`）；  
  H1 = 上月 **24 号**~~本月 3 号，H2 = 本月 9 号~~18 号；窗口互不重叠，4–8 号 / 19–23 号是**间隙**  
  （`open_period` 为空 → 不催办、登录直进自报页）。窗口外提交 → `WindowClosed`。  
  `default_period` = 正在填报的那一期，否则本期（页面默认展示）。
- **格状态（唯一来源 `date_plan.cell_state`）优先级**：**□ 已出勤（已自报）> 过去看事实（×）>  
  计划值（○ 可出勤 / × 不出勤）> 默认出勤（浅色 ○）> – 未登记**。员工端对"可改且未登记"的日子  
  按"**默认每天都出勤**"显示 ○；管理端在**窗口未关**时显示 –（**未登记 ≠ 可出勤**）。
- **单表设计（2026-10-01 补充："避免关联查询"、"自报了就直接改计划表里的状态"）**：  
  `available`（计划）+ **`reported`（该日已自报，□）** 同一行；自报写透  
  `date_plan.mark_reported`（`daily_report` 的 4 个写入口调用），**渲染路径不查自报表**；  
  `is_submitted` 只认 `source != 'report'` 的行。守门测试 `test_admin_matrix_reads_only_plan_table`。
- **过去的日子看事实（2026-10-01 补充）**：`< 今天` → 有自报 □ / 没自报 ×（**计划值不参与**），  
  过去没有 `–` 这一态；员工端同口径（行内"未自报（按不出勤）"）。
- **员工端交互（2026-10-01 补充）**：半月**顺序表**（一天一条），默认全 ○，**点一下 → ×，再点一下 → ○**；  
  **纯 CSS**（整行 label + 隐藏 checkbox + `::after` 切符号），表单区不依赖 Alpine。
- **窗口关了还没填 → "未填默认"（2026-10-01 用户改过一次）**：`unfilled_default()` →
  **老员工漏填 = 不出勤（浅色 ×）**、**本期新入职 = 可出勤（浅色 ○）**、没过截止日不猜（`–`）；
  只对今天及以后生效、过去不追认、登记过的计划优先；**「计划出勤」不含默认不出勤的人**，
  **「未登记人数」= 那天还没填计划的人数**（所以"谁没填"一直看得见，可以催）。
- **待填报提示 + 员工落点（2026-10-01 补充）**：`needs_plan`（**窗口开着且未登记**才需要）+  
  `staff_home`（**唯一来源**：待填报 → `/my/plan`，否则 → `/my/report`，无编号 → `/my/perf`），  
  用在 ① 登录 POST ② `GET /` ③ 中间件拦回员工时。弹窗在 `base.html`（中间件写  
  `request.state.plan_pending`，写明填报期到哪天；计划页自身不弹，**不用 x-cloak**）+「出勤计划」tab 红点。
- **数据**：`staff_date_plans`（`(person_code, plan_date)` 唯一，`available=True` 默认）；只落"不出勤"的例外，
