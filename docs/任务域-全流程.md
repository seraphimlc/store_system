## 0. 名词与硬口径

| 名词 | 表 / 键 | 口径（**唯一来源**） |
|---|---|---|
| 线路 | `bd_line` | 一都三県 131 条；显示名一律 `operator_short + name`（如「京急 本線」「JR東日本 南武線」） |
| 站×线 | `bd_station` | 1,920 行；**同名车站按线路各存一行**（渋谷 ×7 线） |
| 物理车站 | `bd_station_place` | 1,568 个；同 `group_code` + 坐标 <1km 合并；跨线 237 个 |
| **任务** | `bd_task` | **1 物理车站 = 1 任务**；字段 `place_id` / `team_id` / `assign_date` / `state` / `pct` / `start_date` / `done_date` |
| 担当 | `bd_task_assign` | **≤2 人**；必须是该队现役成员；**一人只能在一个队**（DB 部分唯一索引，无跨队借调） |
| 进展 | `bd_task_progress` | **每任务每天一条**（`UNIQUE(task_id, progress_date)`），当天重报=覆盖 |
| 进展字段 | 同上 | `pct`=当前生效值；`reported_pct`/`reported_by`=**员工原值，永不覆盖**；`submitted_by`=写入人；`review_status`(`pending`/`confirmed`/`adjusted`/`rejected`)；`reviewed_by`/`reviewed_at`/`review_note` |
| 日志 | `bd_log` | domain=`task`/`team`/`member`/`station`；**只写不改不删**；任务详情页=进展历史 + 时间线 |

**状态机（`recompute_state`，唯一口径）**

```
pct == 100            → done（已完成）
有担当 或 pct > 0      → doing（进行中）
否则                   → unassigned（未分配/未分担当）
```
> ⚠️ 「未分配」在**页面**上有两个含义，别混：
> **tab 的「未分配」= 车站池**（还没有队伍的物理车站，含从没建过任务的）；
> **按队汇总的「未分配」= 该队已派队但还没分到人**（state 口径）。

**角色与权限**

| 动作 | 管理员 | 队长 | 队员 |
|---|---|---|---|
| 看全部任务 / 导出 / 改派 / 退回池子 | ✅ | ❌ | ❌ |
| 建任务、派队（车站池 → 队） | ✅ | ❌ | ❌ |
| 分派担当（≤2 人） | ✅ | ✅（限本队） | ❌ |
| 上报进展 | ✅ | ✅（本队任何任务可调整） | ✅（**限本人担当**） |
| 确认 / 调整 / 驳回 | ✅ | ✅（限本队） | ❌ |
| 看任务详情 | ✅ 全部 | ✅ 本队 | ✅ 本人担当 |

## 1. 阶段 1 · 定义（管理员）

**目标**：把「一都三県所有线路的车站」变成可派的任务池。

1. **车站库**（`/stations`）：筛选只有 **关键词 + 线路**（用户 2026-10-06："查询条件太挤了，就留俩条件"）。
   表格列：车站 / 线路 / 駅コード / 都道府県 / 物理车站·还经过 / 状态 /（编辑）。
2. **建任务**（`/tasks/new?line=`）：**车站即任务**，可整条线批量建（勾选后建）。任务名=车站名，**任务编号不显示**。
3. **数据来源**：国土数値情報 N02（`scripts/bd_fetch_rail.py` → `scripts/bd_kanto_rail.json`）
   → 导入 `scripts/bd_import_rail.py`（幂等，认领历史 515 站，自动给每个车站建任务）。

**边界**：跨线站（237 个）在每条线的车站库各出现一次但**只有一个物理车站** → 只会有一个任务；
没有 `seq` 的站按站名排序；停用线路仍可建任务但不建议。

## 2. 阶段 2 · 分配

### 2a 派队（管理员：车站池 → 队）—— `/tasks?tab=unassigned`

1. 池子里勾车站（**表头复选框=全选/全不选**；Shift 点=勾一段；按住拖=连续勾选）
2. 选队伍 → 「分配给该队」（提交前**二次确认**：把已选 N 个车站派给这个队？）
3. 结果：`set_task_team` 写 `team_id` + `assign_date`（默认 JST 今天）；
   **换队会清空不属于新队的担当**（并回报清掉几人）；派完即离开池子，进入「已分配」tab。
4. **改派 / 退回池子**：任务详情页（管理员）可「改派队伍」「退回车站池」
   （退回 = 解除队伍 + 清担当 + 清分配日期）。

### 2b 分派担当（队长：任务 → 人）—— `/my/tasks?tab=unassigned`

1. 勾任务（表头全选 / Shift 区间 / 拖拽）→ 选队员 → 「分配给该队员」（可一次分多条）
2. 候选 = **本队现役成员且在职**（离职/停用**阻断**）；旁边带**休假/请假标签**（只提醒不阻断）
3. 上限：一个任务 ≤2 人；分到人后状态 → doing，离开「未分配」

**边界**：队员不能分派（判权在服务层，批量端点同样校验）；
休假/请假只提醒；分配日期为空的任务按「今天」判断可用性。

## 3. 阶段 3 · 执行（员工上报 → 队长审核）

### 3a 员工上报（`/my/tasks?tab=mine`）

- 每行一个 **0–100 滑动条**（step 5）+ 备注 + 「提交今日进展」
- **每天一条**：同一天重报=覆盖；**同值重报不重开审核**（队长刚确认过的不被打回）
- 提交后：`reported_pct`=员工原值、`review_status=pending`（等队长处理）
- 首次提交 → `start_date`；到 100% → `done_date`；**回退清 done_date**

### 3b 队长审核（`/my/tasks?tab=pending`）

| 动作 | 端点 | 效果 |
|---|---|---|
| **确认**（认可原值） | `POST /my/tasks/confirm`（单条）/ `confirm-bulk`（批量） | `review_status=confirmed`，给队员发消息 |
| **调整**（改数值） | `POST /my/tasks/progress` | `review_status=adjusted`，`review_note` 记操作，给队员发消息 |
| **驳回**（把 100% 退回） | `POST /my/tasks/reject` | 仅 `pct==100` 时可用；**保留员工原值** `reported_pct`，理由进 `review_note`（**不覆盖员工备注**），清完成日，给队员发消息 |

管理员在 `/tasks` 列表里也能：**修正进展**（=调整，留痕+发消息）/ **驳回**。
⚠️ **跨天确认**：队长第二天处理昨天的上报 → 定位那条 `pending` 的行（不新建今天的行）。

### 3c 通知（`bd_msg`）

- 触发：**确认 / 调整 / 驳回**（发给他们=该任务**当前担当**）
- 内容：`队员报 X% → Y%` + 操作人 + 备注；链接直达任务详情
- ⚠️ 口径：**员工上报本身不发消息**（避免刷屏）；换人后通知按"当前担当"发（已知偏差，见 §6）

## 4. 阶段 4 · 汇总（管理员 `/tasks`）

1. **统计卡**（与 tab 同口径）：车站池（还没派队）/ 已分配（有队伍·有人管）/ 已完成 / **停滞（≥N 天没动）**
2. **按队汇总**（可点进明细）：总数 / 未分配（已派队没分人）/ 进行中 / 已完成 / 停滞
3. **筛选**：队伍 / 线路（下拉只列有内容的线，数字=该 tab 口径）/ 关键词（**认站名·线路名·运营商·中文**）/
   分配日期区间 / **只看停滞**；分页 50/页
4. **停滞**（唯一口径）：`已分到人` + 未完成 + （从没提交 或 ≥2 天没提交）
5. **导出**（三 sheet，跟随当前筛选）：
   | sheet | 行口径 | 列 |
   |---|---|---|
   | 未分配 | 车站池（物理车站） | 线路 / 站点 |
   | 进行中 | 未完成任务 | 线路 / 站点 / 团队 / 担当 / 进展% / 分配日期 / 开始日 / 最后提交 |
   | 已完成 | pct=100 | 线路 / 站点 / 团队 / 担当 / 完成日期 / 开始日 / 分配日期 / 用时(天) |
6. **任务详情**（`/tasks/{id}`）：状态、担当、进展历史（含**员工原值 vs 生效值**、审核状态、处理人、驳回理由）、
   变更时间线。

## 5. 端到端主流程（一条铁路）

```
定义：/stations 选线 → /tasks/new 勾站建任务（= 每个物理车站一个任务）
  ↓
派队：/tasks?tab=unassigned 勾站 + 选队 → 分配给该队（assign_date=今天）
  ↓
分派：队长 /my/tasks?tab=unassigned 勾任务 + 选队员 → 分配给该队员（state→doing）
  ↓
执行：队员 /my/tasks?tab=mine 拖滑块 + 备注 → 提交（pending，reported_pct=原值）
  ↓
审核：队长 /my/tasks?tab=pending 确认 / 调整（→confirmed/adjusted，发消息）
      若队员报 100% → 队长可驳回（→rejected，进度退回 <100%，清完成日）
  ↓
汇总：管理员 /tasks 看卡片+按队汇总+停滞 → 筛选 → 导出三 sheet
      任务详情页可看"谁改的、改成多少、为什么"
```

## 8. 待实施改造（**口径已确认** 2026-10-06）

> 用户逐条确认的口径（试跑后开工）。**下面 8 条是改造的验收基准**，实现时不得走样。

| # | 确认内容 |
|---|---|
| 1 | **每天派工**：队长每天给队员派当天的任务；**昨天未完成自动延续**（队员今天继续看到），队长只派新的 |
| 2 | **自动确认 = 队长一键全确认**：在自报页把当天全部上报一次确认（不依赖时间点） |
| 3 | **确认后锁定**：只锁**那一天那一条**（进度 + 备注）；第二天任务没完，队员可继续报新的一条 |
| 4 | **管理员只能改进度数字**：点数以队员自报为准（要改点数走"管理员补录自报"） |
| 5 | **回收 / 撤回**：队长**回收** → 回**本队待派**（`team_id` 不变、清担当）；管理员**撤回** → 回**未派队池**；**有进展的任务同样可回收/改派** |
| 6 | **延续不限制**：未完成自动延续后队员手上可能超过 3 个 → 系统**不限制也不提示**（1~3 只是习惯） |
| 7 | **自报合并**：点数 + 当天任务进度在**一个页面、一个表单、一次提交**（同一事务） |
| 8 | **搜索只按线路**：不要运营商维度（**已实施** `34e4ee8`） |

### 改造清单

**A. 数据模型**（迁移 + 本地手工补列）
- `bd_task_assign` 加 **`dispatch_date`**（当天派工）；唯一键 `(task_id, dispatch_date)`（同一天改派=覆盖）
- "未完成自动延续"**不新增行**：队员的「我的任务」= 今天派给他的 ∪ 之前派给他且**未完成**的（查询口径）
- 队长派工时**不限制条数**（按 Q6）

**B. 自报合并**（一页一表单一次提交）
- 页面 = 点数（1点/2点店数）+ 当天 N 个任务的进度滑块 → 一次 POST
- 同一事务写 `staff_daily_reports` + `bd_task_progress`；任一失败**整体回滚**
- 队长视角同一页并列显示「点数 | 进度」，可逐条确认 / 一键全确认

**C. 权限**（两条新规则）
- `can_report`（队员）：该任务**当天已 confirmed → 不可改**（进度+备注一起锁）
- `can_adjust`（管理员）：**要求该天已 confirmed** 才能改；未确认的返回明确提示（不是静默跳转）
- 新端点：`POST /my/tasks/confirm-day`（一键确认当天全部）

**D. 回收 / 空置 / 改派**（有进展也能做）
- 队长**回收**：清担当 → 回本队待派（`state=unassigned`，`team_id` 不变），进展行保留
- 队长**改派**：换人（保留进展；同一天改派=覆盖当天的 `dispatch_date` 行）
- 管理员**撤回**：清队 + 清担当 + 清分配日期 → 回未派队池（复用 `return_to_pool`）
- 全部写 `bd_log`

**E. 管理员按线路操作**
- `/tasks` 按线路列出**该线全部站点**（含已建任务的）→ 勾选**撤回**（已派队未派人 / 有进展未派人）
- 未分配的可批量给团队（已有）
