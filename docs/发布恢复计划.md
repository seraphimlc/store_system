# 发布恢复计划（数据恢复 + 程序恢复）

> 适用：MCP 接入 + 薪资/找平四表重构 + 身份认证（OAuth）上线。
> 原则：**老表零改动**（迁移只建新表/加列；回填只写新表）→ 数据风险可控、回滚路径清晰。
> 配套：`docs/发布计划-MCP上线.md`（正向步骤）、`docs/MCP对接手册.md`（通用做法）。

---

## 0. 发布前必做：三个"预置状态"确认（否则发布后口径会变）

| # | 检查 | 现状（2026-09-26 实测） | 处置 |
|---|---|---|---|
| 1 | **`sys_configs`（全局单值，最新一条生效）** | 线上最新一条是 `250/75/1250` → **8 月会被按 9 月规则算**（已发工资是 68/3000） | **发布前修正**：清空 `sys_configs`（回退按月 env：8月 68/3000、9月 75/1250）或写入正确单值。**注意**：该表无法表达"按月不同"，按月规则只能靠 env 的 `BONUS_*_SCHEDULE` |
| 2 | `staff_visible_from` | 线上为空 → 回退 env 默认 `2026-10` → **员工看不到 8/9 月** | 若要让员工看 8/9 月：设 env `STAFF_VISIBLE_FROM=`（空=不限制）或改配置 |
| 3 | `sealed_months` | 线上**表还不存在**；迁移会建表并**预置 2026-08 封账** | 确认是否要封 8 月：封了则**重传 8 月文件会被拒**（既有设计） |

> 三项都可**发布前**用只读 SQL 核对；修正命令见 §4。

## 1. 恢复分级（按严重程度选路径）

| 级别 | 场景 | 恢复动作 | 数据影响 |
|---|---|---|---|
| **L1 程序回退** | 新代码有 bug（页面/MCP 报错），数据没错 | 回退到上一个 release 符号链接 + `docker compose up -d` | 无 |
| **L2 关停 MCP** | MCP 服务异常，但 web 业务正常 | `docker compose stop mcp` | 无（web 不受影响） |
| **L3 回滚迁移** | 新表/新列导致问题 | `alembic downgrade <上一版本>`（删新表/删新列） | 新表数据丢失（老表不动） |
| **L4 数据恢复** | 老表被误改（理论上不会发生） | 从备份恢复（全库或单表） | 回退到备份时点 |

## 2. 程序恢复（L1 / L2）

### 2.1 回退到上一个 release

```bash
ssh store-prod "ls -1dt /opt/store-settle/releases/*/ | head -3"     # 找到上一个 release
ssh store-prod "ln -sfn /opt/store-settle/releases/<上一个TS> /opt/store-settle/current"
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose up -d --no-deps web"
# MCP 若已起：一并回退
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose up -d --no-deps mcp"
```

**验证**：`curl -s https://store.visitworld.me/healthz`；打开绩效/找平/对账页；MCP 端跑一次工具调用。

### 2.2 只关停 MCP（web 保持新版）

```bash
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose stop mcp"
# Nginx 的 /mcp 会 502；如需干净：临时注释 /mcp location 并 nginx -s reload
```

### 2.3 Nginx 配置回退

```bash
ssh store-prod "cp /etc/nginx/sites-available/<备份的配置> /etc/nginx/sites-available/store-settle && nginx -t && systemctl reload nginx"
```

> 建议：改 nginx 前先 `cp` 一份带时间戳的备份。

## 3. 数据恢复（L3 / L4）

### 3.1 回滚迁移（删新表/新列，老表不动）

```bash
# 查看当前版本与可回退目标
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose exec web alembic current"
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose exec web alembic history | head -12"

# 回到指定版本（例：本次新增链的起点）
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose exec web alembic downgrade <目标revision>"
```

本次发布新增的迁移链（可整段回退）：

```
a1b2c3d4e5f7  mcp_audit_log + sealed_months
b2c3d4e5f6a8  （审计/封账/快照）
c3d4e5f6a7b8  payroll_paid_marks
d4e5f6a7b8c9  payroll_payments
b1c2d3e4f5a6  payroll_payments 溯源列
f6a7b8c9d0e1  payroll_adjusts
a7b8c9d0e1f2  payroll_settlement_links
a4b5c6d7e8f9  api_tokens.expires_at
f7e8d9c0b1a2  oauth_clients / oauth_codes / oauth_refresh_tokens
```

**回退到本次之前**：`alembic downgrade f6c7d8e9f0a1`（本次链的前一个 revision）。

### 3.2 全库恢复（L4，最后手段）

```bash
# 发布前已备份：pre_mcp_<TS>.sql
ssh store-prod "docker exec -i deploy-db-1 psql -U store_settle -d store_settle \
  < /opt/store-settle/backups/pre_mcp_<TS>.sql"
```
> 恢复前**先停 web 与 mcp**（避免写入冲突）：`docker compose stop web mcp`，恢复后再 `up -d`。

### 3.3 单表恢复（更常见、更小影响）

若只有某张表被误改（例如误跑了回填）：

```bash
# 1) 从备份里只导出该表
ssh store-prod "docker exec deploy-db-1 pg_dump -U store_settle -d store_settle \
  -t <表名> --data-only > /tmp/<表名>.sql"        # 需从**备份库**导出（见下）
# 2) 清空并回灌
ssh store-prod "docker exec deploy-db-1 psql -U store_settle -d store_settle -c 'TRUNCATE <表名>;'"
ssh store-prod "docker exec -i deploy-db-1 psql -U store_settle -d store_settle < /tmp/<表名>.sql"
```

**更稳的单表回滚方式**（推荐）：新表都是"可重建"的 → **直接清空新表 + 重跑回填脚本**（幂等）：

```bash
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose exec web \
  python scripts/backfill_prod_new_tables.py"      # 幂等：先清后建
```

### 3.4 回填写错月份的补救

回填只写 `payroll_payments` / `payroll_adjusts` / `payroll_settlement_links`：

```bash
# 清掉这三张新表 → 重跑回填（口径由脚本内 PAID_INSTALLMENTS 决定）
ssh store-prod "docker exec deploy-db-1 psql -U store_settle -d store_settle -c \
  'TRUNCATE payroll_settlement_links, payroll_payments, payroll_adjusts;'"
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose exec web \
  python scripts/backfill_prod_new_tables.py"
```

## 4. 三个预置状态的修正命令（发布前）

### 4.1 `sys_configs`（8 月口径被 9 月规则覆盖）

```bash
# 备份现有行
ssh store-prod "docker exec deploy-db-1 psql -U store_settle -d store_settle -c \
  'SELECT * FROM sys_configs;'"
# 方案 A（推荐）：清空 → 回退按月 env schedule（8月68/3000、9月75/1250）
ssh store-prod "docker exec deploy-db-1 psql -U store_settle -d store_settle -c 'DELETE FROM sys_configs;'"
```
> 回退：把上一步查到的行按原值 `INSERT` 回去。
> **注意**：`/config` 页保存会再次写入全局单值行 → 之后如需按月不同，只能用 env schedule。

### 4.2 `staff_visible_from`

```bash
# 放开（员工可见全部月份）：在 deploy/.env 设 STAFF_VISIBLE_FROM=（空）后重启 web
ssh store-prod "cd /opt/store-settle/current/deploy && docker compose up -d --no-deps web"
```

### 4.3 封账

```bash
# 迁移会预置 2026-08 封账；若不想封：
ssh store-prod "docker exec deploy-db-1 psql -U store_settle -d store_settle -c \
  \"DELETE FROM sealed_months WHERE month='2026-08';\""
```

## 6. 回滚决策表（谁先动）

| 症状 | 先做 | 再做 |
|---|---|---|
| 页面 500 / 功能异常，数据正常 | L1 程序回退 | 定位后重新发布 |
| MCP 连不上 / 工具报错，页面正常 | L2 关停 MCP | 排查后再起 |
| 新表数据不对（找平/台账） | 清新表 + 重跑回填（§3.4） | 仍不对 → L3 回滚迁移 |
| 工资/点数与备份不一致 | **立即 L4 全库恢复** | 复盘（老表本不该被改） |
| OAuth 授权不通 | 暂用 `/my/token` 自助签发兜底 | 修好 OAuth 再切 |
