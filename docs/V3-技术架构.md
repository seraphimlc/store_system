## 核心表（最终）

### 底账与判定
- `imports`：上传文件；字段加 `process_state`（raw_done/confirming/finalized）
- `raw_records`：原样入库，**判定固化在行上**：
  - `clean_status`：valid / dup_master_late / dup_from_sub / dup_crossfile / noref 等（V3 原因枚举 → 单独 reason 枚举列）
  - `filtered_by_raw_id`：被谁挤掉
  - `filter_reason`：枚举原因（见下）
  - `confirm_state`：pending(待员工确认) / approved / disputed / auto_ok(自动认可/免确认)

### 店铺（V3）
- `store_entities`（改造）：`store_id_raw` 一行
  - `is_master` 布尔（或沿用 master_id 自指）
  - `master_id`：自指=主档；从档指向主档实体
  - `raw_data_id`：该店**最早出现**的那条 raw（有效锚点）
  - 从档冗余：`master_store_id` + `master_raw_data_id`（存主档身份，少一次查询）
- `store_merge_logs`：归并留痕

### 员工确认（V3）
- `confirm_tasks`：每 `import × person_code` 一条
  - status: open / approved / disputed / auto_approved(超时)
  - due_at（超时默认认可）
- raw 级 `confirm_state` 记录员工对每条的态度（approved/disputed + note）
- `dispute_logs`：申诉留痕

### 正式表与绩效工资
- `final_records`：入正式表 = 文件全任务完成后，该文件 valid raw 落此表
- `daily_perf` / `month_perf` / `settle_pay`：日绩效/月绩效/结算工资（68点规则）
- 37% 展示字段（不算钱）

### 对账（V3）
- `recon_imports` / `recon_results` / `recon_adjust`：月度对账 Excel、偏差记录、
  下月找平建议

## 判定原因枚举（filter_reason）
- `master_late`：同主档已有更早有效（本店非首次）
- `from_sub`：本条是从档编号，被归并到主档
- `cross_file_dup`：同日同店跨文件重复（自动过滤，免确认）
- `no_ref`：无法归入任何主档/无编号（不算有效，原因可查）

## 主流程（文件级）
1. 上传 parse → raw 入库
2. store 处理（新增 store_id → 建档 → 按店名定主/从；同时维护最早 raw_data_id）
3. 判定（增量）：逐行按 store 主档/从档 + 是否最早 + 跨文件同日同店 → 写
   clean_status/filter_reason/filtered_by
4. 员工建档 + 建 confirm_tasks（import×员工；cross_file_dup 不进任务）
5. 员工确认（看本文件他全部 raw）→ approved/disputed；due 超时 → auto_approved
6. 文件任务全部完成 → finalize：该文件 valid raw → final_records
7. final_records → daily/month perf + settle_pay（68点；37%展示）
8. 月度对账 Excel 导入 → 对账 → 偏差记录 → 下月找平建议
