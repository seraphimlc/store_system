# 批量作业与移动交互：最小化部署方案

更新：2026-11-15（Asia/Singapore）。本方案修正此前将私有镜像桶视为唯一发布前置条件的判断；不代表本次已上线。

## 1. 采用已验证的加密 OSS 中转

沿用 [搜索升级加密 OSS 中转方案](发布-搜索升级-加密OSS中转.md) 和 `scripts/encrypted-release-bundle.mjs`，而非要求新增私有桶或安装 gcloud：

1. 从已提交源码创建不可变 annotated tag `prod-YYYYMMDD-HHmmss`；manifest 记录完整 sourceCommit、实际替换及复用组件。
2. 本地构建 `linux/amd64` 镜像，Docker 归档以随机密钥及 IV 做 AES-256-GCM 认证加密。
3. 调用现有脚本，将仅含 `images.tar.gz.enc`、公开 manifest、`SHA256SUMS` 的 ZIP 上传现有 OSS；沿用现有资源存储配置。前端公开静态资源继续按原 CDN 流程上传并校验。
4. 密钥仅保存在 600 权限文件，通过 SSH 独立传送到服务器 700 权限 release 目录，不进入 OSS、CDN、Git、命令参数或日志。
5. 服务器校验 ZIP 大小、SHA256、条目白名单及密文摘要，认证解密后校验原归档与镜像身份，全部通过才导入。
6. 解密验证成功后删除两端密钥，受控备份及回滚镜像保留。禁止上传明文镜像、runtime.env、数据库备份或其他凭据。

本路径**不要求** `NEXT_RELEASE_BUCKET`、`NEXT_RELEASE_ACCESS_KEY_ID`、`NEXT_RELEASE_SECRET_ACCESS_KEY` 或 gcloud。旧私有桶路径可作为另一种传输方式，不是本次发布阻塞条件。保密性来自认证加密，不来自随机 URL 或 Cache-Control。

```bash
node scripts/encrypted-release-bundle.mjs pack "$RELEASE"
node --env-file-if-exists=.env --env-file-if-exists=.env.next.local \
  scripts/encrypted-release-bundle.mjs upload "$RELEASE"
```

这两条命令只打包、上传，不执行生产解密、迁移或切流。

## 2. 实际基准与最小范围

- current、API、staff、Gateway：`prod-20261115-031440`，sourceCommit `bc3cfd0d70c9226cb13f85691c04c914bb6d5182`。
- admin：`prod-20261113-011447`；Worker：`prod-20261112`。
- Compose 项目 `store-next-prod-20261112`，稳定配置 `/opt/store-next/runtime/compose.json`；生产库 `store_settle`；三个正式服务健康。
- 搜索版白名单明确排除了本次批量操作及门店表单等改动，不能把本地 HEAD 或旧统一版本当作实际线上基准。切流前重新核对 state 和镜像摘要，基准变化则重新比较。

本次拟替换：

| 组件 | 纳入内容 | 排除 / 保留 |
| --- | --- | --- |
| admin 静态资源 | 员工多选及批量状态/软删除、批次勾选与禁用、片区批量团队分配、已有搜索下拉、导航及默认日报 | 财务等其他并行业务改动须排除；复用线上模块或按白名单覆盖 |
| staff 静态资源 | 片区多选分配与最终覆盖提示、50%地图、门店直接选项、照片 ActionSheet、菜单调整 | 保留已上线全量商户搜索、分组、高亮及只读详情，不回退到搜索发布前源码 |
| API | 仅新增授权范围内冻结快照的批次地图读取方法和路由 | 从实际线上 API 镜像叠加该模块的最小差异，保留搜索及认证实现；不得整包替换为工作区服务端 |
| Gateway | 两端 HTML、版本标记及现有代理配置 | HTTPS 语义、原网络、端口、MCP/OAuth 配置不变 |
| Worker / 数据库 / 运行配置 | 不发布、不迁移 | 原 Worker 镜像、任务卷、上传卷、生产 runtime.env、API 资源限额保持不变 |

管理员片区批量分配不扩展为队长专属的网格负责人分配权限。批量操作沿用逐项权限及版本冲突检查，非跨项原子事务，部分失败保留未成功项并报告数量。

## 3. 发布门槛与切流

- 先记录实际线上产物摘要与本次白名单，已提交文件也不能因包含在 HEAD 就自动纳入。
- 两端相关 typecheck/build、批量操作浏览器 mock 验收及批次地图隔离库测试通过；如源码有新改动，仅补跑受影响检查。此前服务端类型错误是否已修复须以当前检查为准，不沿用上次失败结果。
- 正式 amd64 候选在隔离恢复库及独立任务目录验证，不消费正式队列，不用生产业务数据写 fixture。地图验证不付费调用供应商，不读取 raw_records。
- 备份当前 state、Compose、Nginx、运行配置；由于包含 API 变更，按生产手册取得并验证数据库备份及现有恢复演练证据。
- 以当前实际生产运行目录为准，持有发布锁后执行短维护、请求/任务排空、优雅停止及更新流程。Worker 镜像保持原版；若维护需要暂停，只恢复同一原 Worker，不能增加消费者。
- API 健康后启动 Gateway，确认本地入口、公网 ready、release 头、两端 HTML 与 CDN 资源摘要；只读验收默认日报、菜单、批次地图、员工/片区批量入口及原商户搜索。线上不执行真实批量业务写入作为探针。
- 全部通过才更新 production-state，分别记录 apiRelease、adminRelease、staffRelease、workerRelease 和回滚点。

## 4. 回滚

任一镜像身份、候选、健康、资源或页面验收失败，恢复本次快照的 Compose、API/Gateway 镜像和 Nginx；保留同一业务库、任务/上传卷及新产生数据。不倒灌旧库、不删除搜索派生结构或日志、不启动旧 Python 系统。回滚目标是切换前实际运行版本，而不是手册示例版本。
