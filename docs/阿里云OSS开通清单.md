# 阿里云 OSS 开通清单（员工打卡照片存储用）

> 用途：员工打卡的**门头照片**存到 OSS（服务器本地不落照片）。
> 本文分两部分：**中文要点（内部用）** + **日本語手順書（直接转给客户照着做）**。
> 事实核对时间：2026-09-27；价格为海外地域按量计费的量级估算，最终以阿里云官方价格页为准。

## 一、内部要点（中文）

### 1. 谁申请、谁持有
- 客户用**自己的阿里云账号**开通（建议企业实名认证账号），Bucket、数据、账单都归客户。
- **凭据必须是 RAM 子账号的 AccessKey，不要用主账号 AK**（主账号 AK 权限等于整个账号，一旦泄漏后果不可控）。
- 我们只在服务器 `deploy/.env` 里配置，**不进代码库、不写进任何文档**。

### 2. 要开通的东西（3 件）
1. **OSS 服务**（按量付费，无最低消费、无月租）；
2. **1 个私有 Bucket**；
3. **1 个 RAM 子账号 + 最小权限策略**（只允许操作该 Bucket 下 `checkins/` 前缀）。

### 3. 规格建议
| 项 | 取值 | 理由 |
|---|---|---|
| Bucket 名称 | `visit-settle-checkin`（全局唯一，被占用就加后缀） | 用途清晰 |
| 地域 | **日本（东京）ap-northeast-1** | 与线上服务器同区域，上传/下载都在日本境内，延迟低 |
| 读写权限 | **私有** | 照片含门店信息，绝不公开可读；取图走我们登录态鉴权路由 |
| 存储类型 | **标准存储** | 低频访问型不适合"随时可能被翻出来核查"的场景 |
| 服务端加密 | 可选（SSE-OSS 即可） | 增加一道保险 |
| CORS | **不需要配置** | 走服务端代理上传，浏览器不直连 OSS |
| 版本控制 / 静态网站 | 都**不开** | 用不上 |

### 4. 费用估算（按 34 人 × 15 家/日 × 22 日 ≈ 11,200 张/月，单张约 300KB）
| 项目 | 计算 | 估算 |
|---|---|---|
| 存储 | 一年约 40GB × $0.017/GB/月 | ≈ **$0.7/月** |
| 上传（公网入流量） | **免费** | $0 |
| 下载（外网流出流量） | 按每月核查浏览约 5GB × $0.08~0.12/GB | ≈ **$0.5/月** |
| API 请求费 | 每月约 2.3 万次 PUT/GET | 可忽略 |
| **合计** | | **每月 1 美元量级（约 ¥10 以内）** |

> 阿里云 OSS 的**上传不收费、只有下载收费**，这是它对本场景特别划算的原因。最终单价以[官方价格页](https://www.aliyun.com/price/product#/oss/detail)所选地域显示为准。

### 5. 保留与清理
- 照片**保留 24 个月**，由我们的脚本按月删除（删对象 + 在库里标记"无图"，记录本身不删）；
- 建议客户在 OSS 侧再配一条**生命周期兜底规则**（例如对象创建 900 天后删除或转归档），防止我们的脚本因故障没跑而无限累积。

### 6. 要客户回给我们的东西
1. **AccessKey ID / AccessKey Secret**（RAM 子账号的）
2. **Bucket 名称** + **Region/Endpoint**（东京为 `oss-ap-northeast-1.aliyuncs.com`）
3. 确认 Bucket 读写权限为「私有」
4. 交付渠道：**不要微信/邮件明文**，用密码管理器或一次性链接

### 7. 我方配置方式（对应环境变量）

| 环境变量 | 值来源 |
|---|---|
| `VISIT_CHECKIN_STORAGE` | `oss`（本地开发用 `local`，**生产只用 `oss`**） |
| `VISIT_OSS_ENDPOINT` | 例 `oss-ap-northeast-1.aliyuncs.com` |
| `VISIT_OSS_BUCKET` | 客户创建的 bucket 名 |
| `VISIT_OSS_AK` / `VISIT_OSS_SK` | RAM 子账号 AccessKey |
| `VISIT_OSS_PREFIX` | 默认 `checkins/` |

配在线上 `deploy/.env`，**不进代码库**；改完重启 web 容器即生效。相关开关：`VISIT_CHECKIN_RETENTION_MONTHS`（默认 24）、`VISIT_CHECKIN_MAX_PHOTOS` / `VISIT_CHECKIN_MAX_PHOTO_MB`（默认 5 / 5）。

# 阿里云（Alibaba Cloud）OSS 開通手順

対象：従業員チェックイン機能で撮影する**店舗外観写真**の保存先
所要時間：約20〜30分
ご準備いただくもの：貴社の阿里云（Alibaba Cloud）アカウント、クレジットカードまたはお支払い方法

## 0. 事前にご確認いただきたいこと

- アカウント・バケット・データ・ご請求はすべて**貴社名義**で作成いただきます（当社は費用を負担いたしません）。
- 当社にお渡しいただく認証情報は、**必ず「RAM ユーザー（サブアカウント）」の AccessKey** にしてください。**メインアカウントの AccessKey は使用しないでください**（権限が強すぎるため、万一漏えいした場合の影響が甚大です）。
- 写真は**サーバー側のローカルディスクには保存しません**。すべて OSS に保存されます。

## 1. OSS サービスの開通

1. https://www.aliyun.com/ にログインします。
2. コンソール →「オブジェクトストレージサービス OSS」を開きます。
3. 初回の場合はサービスを**有効化**します（従量課金・最低利用料金なし）。

## 2. バケットの作成

「バケットの作成」から、以下の設定で作成します。

| 項目 | 設定値 |
|---|---|
| バケット名 | `visit-settle-checkin`（世界で一意。既に使われている場合は末尾に数字等を追加） |
| リージョン | **日本（東京）ap-northeast-1** |
| ストレージクラス | **標準ストレージ** |
| アクセス権限（ACL） | **非公開（Private）** |
| サーバー側の暗号化 | 任意（SSE-OSS を推奨） |
| バージョニング / 静的サイトホスティング | 使用しません（オフのまま） |
| CORS 設定 | **不要です**（アップロードは当社サーバー経由のため、ブラウザから OSS へ直接アクセスしません） |

> **アクセス権限は必ず「非公開」**にしてください。写真には店舗情報が含まれるため、公開設定は避けていただく必要があります。写真の閲覧は当社システムのログイン認証を経由してのみ行います。

## 3. RAM ユーザー（サブアカウント）の作成

1. コンソール →「RAM アクセス制御」→「ユーザー」→「ユーザーの作成」。
2. ログイン名を入力し、**「プログラミングによるアクセス」のみ**にチェック（コンソールログインは不要）。
3. 作成後に表示される **AccessKey ID / AccessKey Secret を控えてください**（Secret は再表示できません）。

## 4. 最小権限のポリシーを付与

「権限ポリシー」→「ポリシーの作成」→「スクリプト編集」で、以下の内容をそのまま貼り付けて作成し、上記ユーザーにアタッチします。

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:GetObject",
        "oss:DeleteObject",
        "oss:AbortMultipartUpload",
        "oss:ListParts"
      ],
      "Resource": [
        "acs:oss:*:*:visit-settle-checkin/checkins/*"
      ]
    },
    {
      "Effect": "Allow",
      "Action": ["oss:ListObjects"],
      "Resource": ["acs:oss:*:*:visit-settle-checkin"],
      "Condition": {"StringLike": {"oss:Prefix": ["checkins/*"]}}
    }
  ]
}
```

> 上記は「当該バケットの `checkins/` フォルダ以下だけを読み書きできる」権限です。バケット名を変更された場合は `Resource` 内の名前も合わせて変更してください。
> `AliyunOSSFullAccess`（OSS 全体の権限）は付与しないでください。

## 5. ライフサイクル（任意・推奨）

「バケット」→「ライフサイクル」で、以下のルールを追加いただくことを推奨します。

- プレフィックス：`checkins/`
- 操作：オブジェクト作成後 **900日** で削除（またはアーカイブへ移行）

> 当社側でも**24か月**を目安に写真を削除する運用を行います。こちらはその**保険**としての設定です。

## 6. ご費用の概算

想定利用量（従業員34名 × 1日15件 × 月22日 ≒ 11,200枚/月、1枚約300KB）：

| 項目 | 概算 |
|---|---|
| ストレージ（1年で約40GB） | 月 約0.7米ドル |
| アップロード（公網イン流量） | **無料** |
| ダウンロード（外部への流出流量、月5GB想定） | 月 約0.5米ドル |
| API リクエスト | ごく僅か（無視できる水準） |
| **合計** | **月1米ドル程度（約10元以内）** |

> OSS は**アップロードが無料・ダウンロードのみ課金**という料金体系のため、本用途では非常に低コストです。正確な単価は[阿里云公式価格ページ](https://www.aliyun.com/price/product#/oss/detail)の該当リージョンをご確認ください。

## 7. 当社へご連携いただく情報

1. RAM ユーザーの **AccessKey ID / AccessKey Secret**
2. **バケット名**および**リージョン / Endpoint**（東京の場合：`oss-ap-northeast-1.aliyuncs.com`）
3. バケットのアクセス権限が「非公開」であることのご確認

> **認証情報の受け渡しは安全な方法でお願いいたします。** チャットやメールへの平文記載は避け、パスワード管理ツールの共有機能や有効期限付きの共有リンクをご利用ください。当社ではサーバーの環境変数にのみ設定し、ソースコードやリポジトリには保存いたしません。

## 8. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| バケット名が作成できない | 世界中で一意のため、既に使用されています。末尾に数字や会社名を追加してください |
| アップロード時に `AccessDenied` | RAM ポリシーの `Resource` 内バケット名が実際の名前と一致しているか確認 |
| `NoSuchBucket` | リージョン（Endpoint）の指定違い。東京リージョンなら `oss-ap-northeast-1.aliyuncs.com` |
| 写真が外部から見えてしまう | バケット ACL が「公開読取り」になっていないか確認（必ず非公開） |
| AccessKey Secret を紛失した | 再表示はできません。RAM ユーザーで新しい AccessKey を作成し、当社へご連携ください（当社側で環境変数を差し替えます） |
