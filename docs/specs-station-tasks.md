### 0.3 域边界（用户 2026-10-03 确认：「结算域和作业域各干各的」）

| 规则 | 守门 |
|---|---|
| **结算域与作业域完全解耦**：任务完成情况**不影响绩效、不影响工资** | 源码级 `test_settlement_code_never_reads_ops_domain`（`app/services/*`、`app/routers/*` 里除 `bd_*` 外**不得出现** `bd_tasks/bd_teams/bd_log/bd_perm/BdTask/...`） |

| 结算域四表**不得出现 `bd_` 列** | 列级 `test_station_tasks_does_not_touch_settlement_tables` |

**唯一允许的接触点（有意为之，不是耦合）**：
1. **身份**：共用 `persons`/`users` + `person_code` —— 同一个人既是巡店员也是队员，不建第二套人；
2. **角色**：`users.role` 多出 `leader`（由 `bd_teams.sync_account_roles` 同步）——
   这是作业域**唯一**允许写的共享字段（**不碰 `persons`**，也只动 `staff`/`leader`，绝不动 `admin`）；
3. **入口**：同一个员工端 tabbar / 登录落点；
4. **派工提醒（第四轮加）**：作业域**只读** `staff_date_plans`（出勤计划）与 `users`（状态），
   **绝不写**；守门测试 `test_availability_reads_never_write`（可用性检查一个表都没碰）。

> 反过来：作业域**只读** `raw_records`（仅上游 P0 的 `bd_store`，做门店宇宙），**不写**结算域任何表。
> ⚠️ 想"让任务完成率影响工资"时必须**先改这条口径并改测试**——现在是被守门测试挡住的。

## 4. 数据模型（2 张新表）

> **硬边界**：只新增 `bd_*` 表，**绝不向结算域四表加列**；**结算域永不读本域**；
> **不读 `raw_records`**（D6/D8）。守门测试 `test_station_tasks_does_not_touch_settlement_tables`。

### 4.1 `bd_station` —— 车站（**车站就是任务**）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Integer PK | |
| `name` | String(64) | 车站名（必填，如 `駒場東大前`） |
| `name_norm` | String(64) | 归一化（NFKC + 去空白），**UNIQUE = 判重键** |
| `team_id` | Integer | **所属团队**（可空 = 还没派活）；→ `bd_team.id` |
| `state` | String(16) | `not_open` 未开放 / `open` 开放 / `doing` 进行中 / `done` 已完成 |
| `start_date` | Date | 开始日（可空） |
| `done_date` | Date | 完成日（可空） |
| `note` | Text | 备注 |
| `updated_by` | String(32) | 最后改动人（`person_code` 或管理员登录名） |
| `created_at` / `updated_at` | DateTime | |

- **状态机**（唯一来源 = 服务层，写死在测试里）：

```
not_open 未开放 ──管理员开放──→ open 开放 ──队长填开始日──→ doing 进行中 ──队长填完成日──→ done 已完成
     ↑                              ↑            │                      │
     └────── 管理员关闭 ────────────┘            └──── 队长/管理员回退 ────┘
```

- **闸门的用途**：`not_open` 的站**队长不能开工、不能填日期**（"未开放站不可开工"，来自执行说明 PDF）；
- `done` ⟺ `done_date` 非空；`doing` ⟺ `start_date` 非空且 `done_date` 为空 —— **日期与状态必须自洽**，
  由服务层统一维护，不接受自相矛盾的提交。

### 4.2 `bd_station_assign` —— 担当（车站 × 队员，1~2 人）

| 字段 | 说明 |
|---|---|
| `id`、`station_id`、`person_code`、`assigned_by`、`assigned_at` | |

- **UNIQUE(`station_id`, `person_code`)**；**上限 2 人 = 应用层规则**（第 3 人报错「一个车站最多 2 个人」）；
- 分派对象**必须是该队现役成员**（`bd_team_member` 且 `end_date IS NULL`）；
- 改派 = 删本站分派行再插（覆盖式，**不留分派历史** —— 用户没要）。

> ⚠️ **为什么不是"一张表装下全部"**：用户的选项写的是"一张表 515 行装下全部"，
> 但 `担当` 是 **1~2 人**、且队员端要按人查"我的站" → 需要一个可索引的子表。
> **其余列全部在 `bd_station` 上**，列表页仍是单表渲染（反范式优先）。

## 8. 关键规则（写死在测试里）

1. `done` ⟺ `done_date` 非空；`doing` ⟺ `start_date` 非空且 `done_date` 空 —— **状态与日期自洽**；
2. **未开放（`not_open`）的站不能开工**：不接受开始日/完成日（报 `NotOpen`），管理员开放后才能填；
3. 一个站最多 **2 名担当**（应用层）；第 3 人报错；担当**必须是该队现役成员**；
4. **队长只能管本队**：服务层用 `station_id` 反查 team + `is_leader_of` 校验，**不信任表单 team_id**；
5. **改所属团队 → 清空该站担当**（原担当不属于新队）；
6. 关闭闸门时若该站已在做 → **只报告，不静默改日期**；
7. **队员端只读**：写端点不接受 `staff`；队员**看不到备注**；
8. 车站名 `name_norm` 判重，**只提示不覆盖**；
9. 批量提交逐条校验：**非法行跳过并回报，不让整批失败**；
10. 一个站只属一个队（用户资料实测：515 站零重叠）；
11. 队长**无在岗账号**时（陈嘉溢队现状）→ 该队页面/总表给出明确提示，**不阻断其他队**。

### 0.12 建任务：按线路选站（2026-10-05 定稿 + 已实现）

| # | 决定 | 口径 |

| 1 | **任务单位** | **1 个物理车站 = 1 个任务**（跨线站只 1 个）。京葉線 10 站给 A + 8 站给 B = **18 个任务** |
| 2 | 为什么 | **派活是滚动的**："并不是这 10 个站作为一个整体任务跑完我再分新的，而是在剩下几个站的时候我就可以再派一个新的给他" → 任务必须细到站、状态独立 |
| 3 | 建任务时能填 | **队伍**（可不选，之后再派）+ **分配日期自动今天**（不做日期输入，任务要跨好几天）。**担当不在这里定**（队长分） |
| 4 | 交互 | 线路=**筛子**（不要求全选，"可以先建到葛西臨海公園站"）→ 站表按 `seq` 排（带里程）→ 逐个勾 / Shift 区间 / 拖拽圈选 / 全选 → 选队 → 建；**已有任务的站禁用**；建完留在本页 |
