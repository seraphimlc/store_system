# Google Maps Platform API Key 申请流程（员工打卡功能用）

> 用途：员工 H5 打卡页需要「嵌入式谷歌地图 + 店铺查询接口」。
> 本文分两部分：**一、内部要点**（我们自己看的）+ **二、客户版操作步骤**（可直接转发给客户）。
> 事实核对时间：2026-09-27；计价口径为 Google 官方 2025-03-01 起的新方案。

---

## 一、内部要点

### 1. 谁申请、谁持有
- **客户自己申请、自己持有**（Google Cloud 项目 + 结算账号都是客户的），我们只是把 key 配到服务器环境变量里，**不写进代码库**。
- 建议客户用**公司 Google Workspace 管理员账号**建项目，不要用某个员工个人账号（人走了 key 就没人能管）。
- 计费走客户的信用卡/结算账号，我们不承担费用。

### 2. 需要客户开通的 API（3 个）
| API | 用途 | 备注 |
|---|---|---|
| **Maps JavaScript API** | H5 里嵌地图、落 pin、拖拽纠偏 | 必开 |
| **Places API (New)** | 店名/地址搜索框（Autocomplete + Text Search） | 必开，**必须是新版 (New)**，旧版已是 legacy |
| Geocoding API | 坐标⇄地址互转 | 可选，用于回显地址 |

### 3. 免费额度与费用（2025-03-01 后）
- 旧的「每月 $200 通用抵扣」**已取消**，改为 **每个 SKU 每月固定免费次数**：**Essentials 10,000 次 / Pro 5,000 次 / Enterprise 1,000 次**。
- 与本功能相关的 SKU：

| SKU | 档位 | 每月免费 | 超出单价 |
|---|---|---|---|
| Dynamic Maps（地图加载） | Essentials | 10,000 | $7.00 / 1,000 |
| Autocomplete Requests（搜索联想） | Essentials | 10,000 | $2.83 / 1,000 |
| Autocomplete Session Usage | Essentials | **无限制·免费** | — |
| Place Details Essentials（取店名/地址） | Essentials | 10,000 | $5.00 / 1,000 |
| Place Details / Text Search **IDs Only** | Essentials | **无限制·免费** | — |

- 日本另加消费税。参考：[官方计价页](https://mapsplatform.google.com/pricing/)、[2025-03 变更说明](https://developers.google.com/maps/billing-and-pricing/march-2025)。

### 4. 我方用量估算（34 人 × 15 家/日 × 22 日 ≈ 11,200 次/月）
| 方案 | 说明 | 估算费用 |
|---|---|---|
| A：全部走谷歌 | 每次打卡都调地图 + 联想 + 详情 | ≈ **$100/月**（约 ¥15,000） |
| **B：本地优先（推荐）** | 搜索先查系统内 4.2 万条店铺主档 + 自己的打卡点位；查不到才走谷歌 | ≈ **$10/月**，多数月落在免费额度内 |

→ 设计上做成 **B**：本地优先 + 谷歌兜底，并且**谷歌额度用尽时自动回落本地检索**（不会因为超额就卡住员工）。

### 5. 要客户回给我们的东西
1. 浏览器用 API Key（**只需这一把**——地图与搜索都在浏览器直连谷歌，我们不做服务端谷歌调用）
2. 项目 ID + 已开通的 API 清单 + 设的配额上限（截图即可）
3. 结算账号负责人（谁付费）
4. 交付渠道：**不要微信/邮件明文**，用密码管理器或一次性链接

### 6. key 没到位之前怎么办
代码按「有 key」写，用环境变量 `VISIT_GOOGLE_MAPS_KEY` 控开关：
- **无 key**：地图用免费 OpenStreetMap 显示定位点（瓦片加载不出来就退化成「无底图选点器」），搜索用系统内店铺主档 + 打卡点位簿 → **功能不中断**；
- **有 key**：只改 env + 重启，自动切到谷歌地图 + Places 搜索，**不需要改代码、不需要重新发布**。
- 切换后需要补一轮验收：地图能加载、搜索能出候选、定位点能拖拽、超额回落正常。

## 二、客户版操作步骤（可直接转发给客户）

### 0. 事前确认

- **请用公司的 Google 账号（推荐 Google Workspace 管理员账号）操作，不要用个人 Gmail。** 避免负责人离职后 key 无人能管。
- 项目与付款**以贵司名义创建**（费用由贵司承担）。
- 付款方式以信用卡（Visa / Mastercard / JCB / American Express）为主；法人发票付款需满足 Google Cloud 的条件，如有需要请联系 Google Cloud 销售。
- 日本地区的费用会**加算消费税**。

### 1. 创建 Google Cloud 项目

1. 打开 https://console.cloud.google.com/ ，用上述账号登录。
2. 顶部项目选择器 →「新建项目」。
3. 输入项目名（例：`visit-settle-maps`）。有组织（Organization）的请建在组织下。
4. 创建完成后，**保持该项目为当前选中项目**（后续步骤都在这个项目内操作）。

### 2. 设置付款信息（结算账号）

1. 左侧菜单「结算」→「创建结算账号」。
2. 国家/地区：日本；币种：JPY；登记信用卡信息。
3. 把创建好的结算账号**关联到第 1 步的项目**。

> 注意：自 2025 年 3 月 1 日起，原有的「每月 200 美元通用抵扣」已取消，改为**按 SKU（功能）每月固定免费次数**（见第 6 步）。另外，新开的 Google Cloud 账号可能享有 90 天 / 300 美元免费试用额度（适用条件请以开通时页面为准）。

### 3. 启用 API（3 个）

「API 和服务」→「库」中搜索下列 API，逐个点击**「启用」**：

| API 名称 | 用途 |
|---|---|
| **Maps JavaScript API** | 网页嵌入地图（必须） |
| **Places API (New)** | 店名 / 地址搜索与输入联想（必须） |
| Geocoding API | 地址与坐标互转（可选） |

> **重要**：店铺搜索必须启用 **「Places API (New)」**（新版）。旧版「Places API」已是遗留（legacy）状态，无法使用新能力。

### 4. 创建 API Key（浏览器用，1 把）

1. 「API 和服务」→「凭据」→「创建凭据」→「API 密钥」。
2. 打开该密钥的「编辑」，**务必设置以下两项限制**：
   - **应用限制**：选「网站」，添加
     - `https://store.visitworld.me/*`
     - `http://127.0.0.1:8000/*`（我方的开发/验证用，不需要可删除）
   - **API 限制**：选「限制密钥」，只勾选 `Maps JavaScript API` 与 `Places API (New)`

> 浏览器端密钥会出现在用户页面上（无法完全隐藏）。Google 推荐用**「来源限制 + API 限制 + 配额上限（第 5 步）」三件套**来防护。
> 如需更严格，可再启用 Maps JavaScript API 的「URL 签名」或「App Check」——需要我方协助可随时提出。

### 5. 用量上限与预算提醒（防止费用失控，建议必做）

1. 「Google Maps Platform」→「配额」中，为每个 API 设置**每日上限**，建议值：
   - Dynamic Maps：2,000 / 日
   - Autocomplete Requests：2,000 / 日
   - Place Details：1,000 / 日

   （本系统在达到上限时会**自动切换为系统内检索**，上限触达不影响现场作业。）
2. 「结算」→「预算和提醒」中，例如设置**每月 10,000 日元**的提醒。

### 6. 免费额度与费用（2025 年 3 月 1 日起）

免费额度按 **SKU 计算、每月重置**：**Essentials 10,000 次 / Pro 5,000 次 / Enterprise 1,000 次**。

本功能用到的主要 SKU：

| SKU | 分类 | 每月免费次数 | 超出单价 |
|---|---|---|---|
| Dynamic Maps（地图加载） | Essentials | 10,000 | $7.00 / 1,000 次 |
| Autocomplete Requests（输入联想） | Essentials | 10,000 | $2.83 / 1,000 次 |
| Autocomplete Session Usage | Essentials | 无限制·免费 | — |
| Place Details Essentials（取店名/地址） | Essentials | 10,000 | $5.00 / 1,000 次 |
| Place Details / Text Search（IDs Only） | Essentials | 无限制·免费 | — |

**本系统的费用概算**（按 34 名员工 × 每日 15 件 × 每月 22 天 ≈ 11,200 件/月）：

- 全部操作都调用 Google 的构成：约 **100 美元/月**（约 15,000 日元）
- **我方推荐构成**（优先使用系统内店铺数据，仅在必要时调用 Google）：约 **10 美元/月**，多数月份可落在免费额度内

### 7. 需要回给我方的信息

1. 第 4 步创建的 **API Key**
2. **项目 ID**、已启用的 API 清单、设置的配额上限（画面截图即可）
3. 结算账号的负责人（谁承担费用）

> **密钥请通过安全渠道交付**：请勿在聊天工具或邮件中明文粘贴，建议使用密码管理器的共享功能或带有效期的共享链接。我方只会写入服务器环境变量，不会保存到源码或代码仓库。

### 8. 常见故障

| 现象 | 原因与处理 |
|---|---|
| 地图显示「For development purposes only」 | 未设置结算账号，或未关联到项目（第 2 步） |
| 搜索没有候选结果 | 未启用 Places API (New)，或密钥的 API 限制未包含它（第 3、4 步） |
| 出现 `RefererNotAllowedMapError` | 来源限制登记遗漏。请精确登记 `https://store.visitworld.me/*`（注意有无 `www`、末尾的 `/*`） |
| 某个 API 报 `REQUEST_DENIED` | 该 API 未在项目中启用 |
| 怀疑密钥泄漏 | 在 Cloud Console 删除并重新签发密钥 → 交付给我方（我方替换环境变量并重启） |

### 9. 密钥到位前的临时运行方式

在 API Key 准备完成之前，**功能也可以先跑起来**：

- 地图显示：使用免费的 OpenStreetMap 显示当前位置
- 店铺搜索：从系统内店铺主档（约 4.2 万条）＋ 历史打卡记录中检索

密钥交付给我方后，**仅需我方修改配置**即可切换到「Google 地图 + Places 搜索」（无需重新开发）。
