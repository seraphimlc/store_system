# 出退勤打卡

## 2026-11-16：首次实现（源码，未上线）

- 员工及队长本人在员工端巡店首页打卡；`/my/attendance` 查看本人记录、申请补卡；队长 `/my/team-attendance` 查看当前本队成员；管理端 `/admin/attendance` 查看全部及处理补卡。
- 现场打卡必须取得新定位，保存经纬度、精度、定位采集时间；定位拒绝、失败、超时不能生成有效打卡。不设地点限制、围栏或持续定位。时间取服务端入库时间，不接受客户端指定现场打卡时间。
- 日本时间每日05:00换日，业务日范围为当日05:00至次日05:00前。每次有效打卡追加保留，最早出勤、最晚退勤及各自位置作为汇总；误打不作废。请求标识防止网络重试或并发重复写入。
- 仅有退勤、没有出勤的记录在队长/管理员动态标记异常。无自动迟到、旷工或工资判定；不改日报、出勤计划或结算数据。
- 记录只关联员工，不保存硬性团队归属。队长必须同时具备当前队长账号角色和有效团队队长成员关系；历史可见范围随当前成员关系变化，成员换队后由新队查看，原队失去权限。
- 补卡为员工本人申请、管理员通过/拒绝，保留原因、申请时间、处理人、处理时间和备注。通过后追加无定位的补卡事件，参与最早/最晚汇总，不伪造现场位置；已处理申请不能重复处理。
- 新增作业域表 `bd_attendance_event`、`bd_attendance_makeup`。显式迁移：`deploy-next/migrations/010-attendance.sql`，启动不自动迁移；业务库/生产库均未自动执行。本地启用前须显式执行迁移，生产按唯一发布手册另行授权。
- 不引入地图SDK或逆地理编码：显示坐标、精度，用户主动点击“查看位置”才打开对应地图链接。客户端定位并非防伪到场证明。
- 回归入口：`node scripts/test-isolated.mjs --file=apps/server/test/attendance.test.ts`；浏览器 `node scripts/test-isolated.mjs --browser --attendance`（mock定位及API，无付费定位/地图调用）。

### 每日提醒确认时机修复

原实现查询成功即写“已提醒”，可能在用户尚未实际看到/处理弹窗时吞掉当日提醒。现改为只有点击“去打卡/稍后再说”才记已提醒；已有出勤仍直接标记免提醒。旧自动标记不沿用，使用ack键，避免旧状态继续压住弹窗。当前已登录首页实际出现居中遮罩Dialog，保留供用户操作，未代点打卡或获取定位。staff类型检查构建及9组隔离浏览器通过，新增“仅打开不写确认标记”断言。
